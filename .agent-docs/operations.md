## 添加新文档时：必须执行的操作

添加或修改任何文件后，**必须**按顺序执行：

- [ ] 更新所在子目录的 `README.md`，添加新文件链接与描述
- [ ] 更新父级 `README.md`（若分类层面有变更）
- [ ] 更新根 `llms.txt`，在对应分类下追加新链接
- [ ] 在 `CHANGELOG/YYYY-MM.md` 中追加操作记录

> **提示**：`01-技术资料` 与 `02-面试指南` 分类编号完全对应，添加任一目录的内容时，应同步在对应目录中添加关联文档，并在文档内添加相互跳转的链接。

## 任务执行流程

> Cloud Agent 存在运行时间限制，以下流程确保任务可中断恢复、支持并发编辑。

### 中断恢复：`_WORKING_` 文件夹

每次编辑任务开始时，在项目根目录创建 `_WORKING_/` 文件夹：

```
_WORKING_/
├── instruction.md    # 用户原始指令
├── plan.md           # 实施计划与分步骤目标
├── status.md         # 当前进度（已完成/进行中/待办）
└── notes.md          # 过程中积累的经验与发现
```

**规则：**
1. 任务开始时创建，任务完全完成时删除
2. 阶段性目标完成后，**必须立即提交代码**，避免因超时丢失进度
3. 下一个 Agent 启动时，首先检查 `_WORKING_/` 是否存在，若存在则恢复上下文继续工作
4. `_WORKING_/` 已被 VitePress 构建器忽略（`srcExclude` 中配置）

### 长文件分块：`__blocks/` 文件夹

对于较长的文件（300+ 行），可拆分为多个块：

```
01-前端/
├── 01-JavaScript基础.md              # 最终拼接后的完整文件
├── __blocks/
│   └── 01-JavaScript基础/
│       ├── _manifest.md              # 块清单：顺序、标题、描述
│       ├── 01-基础类型与变量.md
│       ├── 02-函数与作用域.md
│       └── 03-异步编程.md
```

**`_manifest.md` 格式示例：**

```markdown
# 块清单 — 01-JavaScript基础

| 序号 | 文件 | 标题 | 说明 |
|------|------|------|------|
| 01 | 01-基础类型与变量.md | 基础概念 | 类型、变量、基本语法 |
| 02 | 02-函数与作用域.md | 进阶特性 | 闭包、原型链、异步 |
| 03 | 03-异步编程.md | 异步编程 | Promise、async/await |
```

**拼接命令：**

```bash
# 按 _manifest.md 中的顺序拼接各块为完整文件
cat __blocks/01-JavaScript基础/01-*.md __blocks/01-JavaScript基础/02-*.md __blocks/01-JavaScript基础/03-*.md > 01-JavaScript基础.md
```

**规则：**
1. `__blocks/` 放在与目标文件同级目录下
2. 文件夹内必须包含 `_manifest.md`
3. 所有块编辑完成后，按清单顺序拼接为完整文件
4. 核心目的：多个 subagent 可并发编辑不同块
5. `__blocks/` 已被 VitePress 构建器忽略（`srcExclude` 中配置）

### 内容索引与去重：`_index.md`

每个文档目录下维护 `_index.md`，记录所有文档的二级标题索引：

```markdown
# 目录索引 — 分类名

## 01-文档A.md
### 章节标题1
### 章节标题2

## 02-文档B.md
### 章节标题1
### 章节标题2
```

**规则：**
1. 编辑任务过程中持续更新（不存在则创建）
2. 索引精确到**二级标题（`##`）**级别
3. 去重职责：编写完成后回顾 `_index.md`，确保不同文档间无完全重复主题（同主题不同层次/场景可保留）
4. `_index.md` 已被 VitePress 构建器忽略（`srcExclude` 中配置）

## 注意事项

- 不要删除现有目录结构中的 `README.md` 文件
- 不要跳过编号，序号应连续；若需在中间插入，保持已有序号不变，新内容使用递增序号
- 所有链接使用**相对路径**
- `AGENTS.md` 保持精简（TOC 式），详细说明应在本文件或对应领域文档中
- 每篇技术文档**必须**包含「常见陷阱与最佳实践」章节
- 每篇技术文档**建议**包含开头 TL;DR 速览（5-8 条核心要点）

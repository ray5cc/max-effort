## 1. 为什么需要服务端安全与鉴权

- **数据与合规**：个人数据、支付、健康等敏感信息泄露会触发监管与巨额罚款。
- **业务可信**：越权操作、假冒请求会直接导致资金损失或业务中断。
- **复杂依赖**：多端、多租户、第三方集成让身份与权限边界更易出错。

> 类比：写有门禁、监控和访客登记的写字楼。身份验证是门禁，权限是楼层访问卡，审计是访客登记，防护是保安与摄像头。

## 2. 核心概念（是什么）

- **认证 (Authentication)**：验证“你是谁”。常见：密码、OTP、MFA、FIDO2、SAML、OIDC。
- **授权 (Authorization)**：验证“你能做什么”。常见模型：
  - **RBAC**：角色→权限，易管理但粒度粗。
  - **ABAC**：基于属性（主体/资源/环境），灵活但策略复杂。
  - **PBAC/Policy-as-Code**：如 OPA/Rego，将策略代码化。
- **会话与令牌**：Cookie+Session、JWT、PASETO、Opaque Token。
- **零信任**：持续验证身份与设备状态，最小权限、强审计。
- **审计与可追溯**：谁在何时对哪个资源做了什么操作，便于追责与溯源。

## 3. 鉴权与防护设计（怎么做）

### 3.1 身份与令牌

- **OIDC 授权码 + PKCE**：前后端分离/移动端标准流程，防拦截重放。
- **JWT vs Opaque**：JWT 自包含、可离线验证但有撤销难题；Opaque 需查存储但易做撤销与轮转。生产常用短 JWT + 长 Refresh Opaque。
- **密钥管理**：使用 JWK + kid 轮换，私钥存 HSM/KMS；最短可行过期时间。

### 3.2 权限校验与策略

- **分层**：网关粗粒度拦截 + 服务侧细粒度校验。
- **租户隔离**：请求头携带 `tenant_id`，在数据层做行级/库级隔离；多租户 ID 不可被客户端控制直接决定权限（需服务端映射）。
- **策略引擎**：OPA/Rego 或 Casbin；策略随代码评审、版本化。

### 3.3 防护与输入验证

- **CSRF 防护**：SameSite=Lax/Strict；状态变更接口要求 CSRF Token；对跨域使用双提交 Cookie。
- **XSS 防护**：输出编码、CSP、限制内联脚本；模板默认转义。
- **SQL/NoSQL 注入**：参数化查询、最小权限账号；禁止字符串拼接。
- **重放与暴力破解**：Nonce/时间戳签名、速率限制、IP/Device Fingerprint、MFA。
- **文件与命令安全**：上传白名单/内容检测；避免将用户输入传入 shell。

### 3.4 传输与存储安全

- **TLS**：强制 HTTPS/HSTS；TLS 1.2+；关闭弱套件。
- **敏感数据保护**：静态加密（KMS）、传输加密、字段级加密（如身份证、卡号）；日志脱敏。
- **密钥与配置**：不写入代码库，使用 Secrets 管理（Vault/KMS/Parameter Store）。

### 3.5 审计与响应

- **审计日志**：记录主体/资源/动作/结果/来源 IP/UA/trace_id；不可篡改存储。
- **告警**：异常登录、权限提升、同账号多地同时登录、暴力破解尝试。
- **应急**：令牌撤销/黑名单、密钥轮换、批量登出。

## 4. 实践案例：SaaS 多租户零信任网关

**目标**：租户隔离、防越权、可追溯；客户端含 Web/移动/第三方集成。

1) **身份提供**：OIDC 授权码 + PKCE，ID Token 短期，Refresh Token Opaque 存储于授权服务器。  
2) **网关**：验证 Access Token（JWK 缓存），提取 `sub/tenant_id/scope`，做粗粒度 RBAC 与速率限制，附带 `x-user-id` 注入后端。  
3) **服务侧**：校验资源所属租户与角色；关键写操作要求设备可信状态或 MFA；权限策略用 OPA。  
4) **数据层**：按租户库/Schema 隔离或行级过滤，强制查询带租户条件；审计日志落地不可变存储。  
5) **撤销与轮换**：Refresh Token 存储+黑名单；Access Token TTL 15 分钟；KMS 管理私钥，每周轮换 kid。  
6) **监控**：告警异常登录、权限提升、同账号异地并发；定期回放安全剧本。

ASCII 示意：

```
Client ─▶ OIDC AuthZ + PKCE ─▶ Gateway (JWT verify + RBAC + RateLimit)
                               │
                               └▶ Services (OPA/Casbin policy + tenant guard)
                                      │
                                      └▶ Data (row/schema isolation + audit log)
```

## 5. 常见陷阱与最佳实践

- **陷阱：长效 JWT 不可撤销** → Access Token 短期 + Refresh Opaque + 旋转 + 黑名单。  
- **陷阱：仅前端校验租户/角色** → 服务端必须二次校验，且在数据层强制租户过滤。  
- **陷阱：缺少审计** → 核心写操作必须记录不可篡改日志，并与 Trace 关联。  
- **最佳实践**：
  - 默认拒绝：最小权限、显式授权。
  - 策略即代码：版本化、评审、回滚。
  - 密钥与配置外置化：KMS/Secrets Manager，定期轮换。
  - “安全左移”：在代码评审与 CI 加入依赖漏洞扫描与策略测试。

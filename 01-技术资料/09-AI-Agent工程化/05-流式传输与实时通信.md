# 流式传输与实时通信

> 从 SSE 到 WebSocket，深入解析 AI 应用中流式数据传输的协议选型、工程实现与性能优化

## 相关链接

- 对应面试题：[流式传输与实时通信面试题](../../02-面试指南/09-AI-Agent工程化面试/05-流式传输与实时通信面试题.md)

## TL;DR 速览

- **SSE（Server-Sent Events）** 是 LLM 流式输出的事实标准，单向、轻量、HTTP 原生支持
- **WebSocket** 适合双向实时通信场景（如协作编辑、实时语音），但对 LLM 单向流式输出来说过于复杂
- **Fetch Streaming**（ReadableStream API）是现代浏览器处理 SSE 的最佳方式
- 流式输出的三大工程挑战：**背压控制、错误恢复、中间代理兼容**
- Nginx 的 `proxy_buffering off` 是流式代理的第一条必改配置
- **AG-UI 协议** 是 Agent-UI 通信的新兴标准，扩展了 SSE 的语义

## 1. 为什么 AI 应用需要流式传输？

### 1.1 用户体验的关键

LLM 生成一段 500 字的回复通常需要 5-15 秒。如果等全部生成完才返回，用户体验极差——就像给朋友发消息，对方要 15 秒后一次性把整段话发出来。

**流式输出让 LLM 像"打字"一样逐字显示**，用户可以立即开始阅读，感知延迟从 15 秒降低到 200ms（首 Token 延迟）。

**类比**：流式传输就像水龙头——你不需要等整个水塔装满才能用水，打开水龙头就能立即获得水流。

### 1.2 延迟指标

| 指标 | 说明 | 目标值 |
|------|------|--------|
| TTFT (Time to First Token) | 用户按发送到看到第一个字 | < 500ms |
| TPS (Tokens per Second) | 每秒显示的 Token 数 | > 30 tokens/s |
| Total Latency | 从发送到完全接收 | 取决于输出长度 |

## 2. 协议选型

### 2.1 三种协议对比

| 特性 | SSE | WebSocket | HTTP Streaming |
|------|-----|-----------|----------------|
| 方向 | 服务端→客户端（单向） | 双向 | 服务端→客户端 |
| 协议 | HTTP/1.1, HTTP/2 | 独立协议 (ws://) | HTTP/1.1, HTTP/2 |
| 数据格式 | 文本 (UTF-8) | 文本 + 二进制 | 任意 |
| 自动重连 | 浏览器原生支持 | 需手动实现 | 需手动实现 |
| 代理兼容 | 优秀 (标准 HTTP) | 中等 (需 Upgrade) | 优秀 |
| 并发限制 | HTTP/1.1 每域名 6 个 | 无限制 | HTTP/1.1 每域名 6 个 |
| 适用场景 | LLM 流式输出 | 实时协作、语音 | 文件下载、日志流 |

### 2.2 为什么 LLM 场景首选 SSE？

1. **LLM 输出是单向的** — 用户发完请求后，只需要接收 AI 的逐字输出
2. **HTTP 原生** — 不需要协议升级，防火墙和代理天然支持
3. **自动重连** — EventSource API 内置断线重连机制
4. **简单** — 服务端只需要返回特定格式的文本流

### 2.3 OpenAI SSE 协议格式

```
HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive

data: {"id":"chatcmpl-xxx","choices":[{"delta":{"content":"Hello"}}]}

data: {"id":"chatcmpl-xxx","choices":[{"delta":{"content":" world"}}]}

data: {"id":"chatcmpl-xxx","choices":[{"delta":{"content":"!"}}]}

data: [DONE]
```

**协议规则**：
- 每个事件以 `data: ` 开头
- 事件之间用空行分隔 (`\n\n`)
- `data: [DONE]` 标记流结束
- 可选 `event:` 字段指定事件类型
- 可选 `id:` 字段用于重连时恢复

## 3. SSE 深度工程实践

### 3.1 SSE 数据格式规范

```
# 基本格式
data: 消息内容\n\n

# 多行数据
data: 第一行\n
data: 第二行\n\n

# 带事件类型
event: token\n
data: {"content": "Hello"}\n\n

# 带 ID（用于重连）
id: 42\n
event: token\n
data: {"content": "world"}\n\n

# 设置重连间隔
retry: 3000\n\n
```

### 3.2 Anthropic 流式协议（与 OpenAI 的差异）

```
event: message_start
data: {"type":"message_start","message":{"id":"msg_xxx","role":"assistant"}}

event: content_block_start
data: {"type":"content_block_start","index":0,"content_block":{"type":"text","text":""}}

event: content_block_delta
data: {"type":"content_block_delta","index":0,"delta":{"type":"text_delta","text":"Hello"}}

event: content_block_delta
data: {"type":"content_block_delta","index":0,"delta":{"type":"text_delta","text":" world"}}

event: content_block_stop
data: {"type":"content_block_stop","index":0}

event: message_stop
data: {"type":"message_stop"}
```

## 4. 后端流式实现

### 4.1 Python FastAPI 实现

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import asyncio
import json

app = FastAPI()

@app.post("/v1/chat/completions")
async def chat_completions(request: ChatRequest):
    if not request.stream:
        # 非流式：等待完成后一次返回
        result = await llm.generate(request.messages)
        return result
    
    # 流式：逐 Token 返回
    async def event_stream():
        try:
            async for token in llm.generate_stream(request.messages):
                chunk = {
                    "id": f"chatcmpl-{uuid4()}",
                    "object": "chat.completion.chunk",
                    "choices": [{
                        "index": 0,
                        "delta": {"content": token},
                        "finish_reason": None
                    }]
                }
                yield f"data: {json.dumps(chunk)}\n\n"
            
            # 发送结束标记
            final_chunk = {
                "id": f"chatcmpl-{uuid4()}",
                "choices": [{"index": 0, "delta": {}, "finish_reason": "stop"}]
            }
            yield f"data: {json.dumps(final_chunk)}\n\n"
            yield "data: [DONE]\n\n"
            
        except Exception as e:
            error_data = {"error": {"message": str(e), "type": "server_error"}}
            yield f"data: {json.dumps(error_data)}\n\n"
    
    return StreamingResponse(
        event_stream(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "Connection": "keep-alive",
            "X-Accel-Buffering": "no",  # 禁用 Nginx 缓冲
        }
    )
```

### 4.2 Node.js Express 实现

```javascript
app.post('/v1/chat/completions', async (req, res) => {
  if (!req.body.stream) {
    const result = await llm.generate(req.body.messages);
    return res.json(result);
  }
  
  // 设置 SSE 响应头
  res.writeHead(200, {
    'Content-Type': 'text/event-stream',
    'Cache-Control': 'no-cache',
    'Connection': 'keep-alive',
    'X-Accel-Buffering': 'no'
  });
  
  try {
    const stream = await llm.generateStream(req.body.messages);
    
    for await (const token of stream) {
      const chunk = {
        id: `chatcmpl-${crypto.randomUUID()}`,
        choices: [{ index: 0, delta: { content: token } }]
      };
      res.write(`data: ${JSON.stringify(chunk)}\n\n`);
    }
    
    res.write('data: [DONE]\n\n');
    res.end();
    
  } catch (error) {
    res.write(`data: ${JSON.stringify({ error: error.message })}\n\n`);
    res.end();
  }
  
  // 处理客户端断开
  req.on('close', () => {
    stream?.cancel();  // 取消 LLM 生成
  });
});
```

### 4.3 背压控制

当客户端消费速度慢于服务端生产速度时，需要背压控制：

```python
async def event_stream_with_backpressure():
    buffer = asyncio.Queue(maxsize=100)  # 有界缓冲区
    
    async def producer():
        async for token in llm.generate_stream(messages):
            await buffer.put(token)  # 缓冲区满时自动等待
        await buffer.put(None)  # 结束标记
    
    asyncio.create_task(producer())
    
    while True:
        token = await buffer.get()
        if token is None:
            break
        yield f"data: {json.dumps({'content': token})}\n\n"
```

### 5.1 方式一：EventSource API（浏览器原生）

```javascript
// 优点：内置自动重连

source.onmessage = (event) => {

    source.close();
    return;
  }

  appendToChat(data.choices[0].delta.content);
};

source.onerror = (error) => {
  console.error('SSE Error:', error);
  // EventSource 会自动重连

```

### 5.2 方式二：Fetch + ReadableStream（推荐）

```typescript
async function streamChat(messages: Message[]): AsyncIterable<string> {
  const response = await fetch('/v1/chat/completions', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ messages, stream: true }),
    signal: abortController.signal  // 支持取消
  });
  
  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }
  
  const reader = response.body!.getReader();
  const decoder = new TextDecoder();
  let buffer = '';
  
  try {
    while (true) {
      const { done, value } = await reader.read();
      if (done) break;
      
      buffer += decoder.decode(value, { stream: true });
      
      // 按行解析 SSE 事件
      const lines = buffer.split('\n');
      buffer = lines.pop() || '';  // 保留不完整的最后一行
      
      for (const line of lines) {
        if (!line.startsWith('data: ')) continue;
        const data = line.slice(6);
        if (data === '[DONE]') return;
        
        const parsed = JSON.parse(data);
        const content = parsed.choices?.[0]?.delta?.content;
        if (content) yield content;
      }
    }
  } finally {
    reader.releaseLock();
  }
}

// 使用
for await (const token of streamChat(messages)) {
  updateUI(token);
}
```

## 6. 反向代理与 CDN 配置

### 6.1 Nginx SSE 代理

```nginx
location /v1/ {
    proxy_pass http://backend:8000;
    
    # 关键 SSE 配置
    proxy_http_version 1.1;
    proxy_set_header Connection "";      # 清除 hop-by-hop header
    proxy_buffering off;                  # 禁用响应缓冲
    proxy_cache off;                      # 禁用缓存
    chunked_transfer_encoding on;
    
    # 超时配置
    proxy_read_timeout 300s;              # LLM 生成可能较慢
    proxy_send_timeout 300s;
    
    # SSE 特定
    proxy_set_header X-Accel-Buffering no;
    
    # 传递请求信息
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

## 7. 错误处理与重连机制

### 7.1 流式错误处理

```typescript
class StreamingError extends Error {
  constructor(
    message: string,
    public readonly type: 'network' | 'parse' | 'server' | 'timeout',
    public readonly retryable: boolean
  ) {
    super(message);
  }
}

async function* resilientStream(messages: Message[], maxRetries = 3) {
  let retries = 0;
  let lastEventId = '';
  
  while (retries < maxRetries) {
    try {
      const response = await fetch('/v1/chat/completions', {
        method: 'POST',
        headers: {
          'Content-Type': 'application/json',
          'Last-Event-ID': lastEventId  // 断点续传
        },
        body: JSON.stringify({ messages, stream: true })
      });
      
      // ... 解析流式数据 ...
      return;  // 成功完成
      
    } catch (error) {
      retries++;
      if (retries >= maxRetries) throw error;
      
      // 指数退避
      const delay = Math.min(1000 * Math.pow(2, retries), 10000);
      await new Promise(r => setTimeout(r, delay));
    }
  }
}
```

## 8. AG-UI 协议

### 8.1 概述

AG-UI（Agent-User Interaction Protocol）是新兴的 Agent-UI 通信标准，扩展了 SSE 的语义：

```
传统 SSE：只有文本流
  data: {"content": "Hello"}
  data: {"content": " world"}

AG-UI：丰富的事件类型
  event: TEXT_MESSAGE_START
  data: {"messageId": "msg-1", "role": "assistant"}
  
  event: TEXT_MESSAGE_CONTENT
  data: {"messageId": "msg-1", "delta": "Hello"}
  
  event: TOOL_CALL_START
  data: {"toolCallId": "tc-1", "name": "search_web"}
  
  event: TOOL_CALL_ARGS
  data: {"toolCallId": "tc-1", "delta": "{\"query\": \"weather\"}"}
  
  event: TOOL_CALL_END
  data: {"toolCallId": "tc-1"}
  
  event: STATE_UPDATE
  data: {"status": "thinking", "progress": 0.5}
```

### 8.2 AG-UI 的价值

- **标准化**：前端不需要为每种 Agent 框架写不同的解析逻辑
- **丰富语义**：工具调用、状态更新、进度条等都有标准事件
- **可组合**：多个 Agent 的事件流可以合并显示

## 9. 常见陷阱与最佳实践

### ❌ 陷阱 1：使用 WebSocket 做 LLM 流式输出

```javascript
// ❌ 错误：为单向流式输出使用 WebSocket（过于复杂）
const ws = new WebSocket('ws://api/chat');
ws.onmessage = (event) => { ... };
// 需要手动处理重连、心跳、协议升级...

// ✅ 正确：使用 SSE/Fetch Streaming（简单、HTTP 原生）
const response = await fetch('/api/chat', { method: 'POST', ... });
const reader = response.body.getReader();
```

### ❌ 陷阱 2：不处理不完整的 SSE 行

```javascript
// ❌ 错误：假设每次 read() 返回完整的行
const { value } = await reader.read();
const line = decoder.decode(value);
const data = JSON.parse(line.slice(6));  // 可能崩溃！

// ✅ 正确：维护缓冲区，按 \n 分割
buffer += decoder.decode(value, { stream: true });
const lines = buffer.split('\n');
buffer = lines.pop() || '';  // 保留不完整的最后一行
```

### ❌ 陷阱 3：忘记在 Nginx 中关闭 buffering

```nginx
# ❌ 错误：Nginx 默认开启 proxy_buffering
# 所有 SSE 数据会被缓冲，直到缓冲区满才发送
# 用户看到的效果：等很久后一大段文字突然出现

# ✅ 正确：显式关闭所有缓冲
proxy_buffering off;
proxy_cache off;
proxy_set_header X-Accel-Buffering no;
```

### ❌ 陷阱 4：流式响应没有错误处理

```python
# ❌ 错误：异常导致连接突然断开，客户端不知道发生了什么
async def stream():
    async for token in llm.generate(messages):
        yield f"data: {json.dumps({'content': token})}\n\n"
    # 如果这里抛异常，客户端只会看到连接断开

# ✅ 正确：在流中发送错误事件
async def stream():
    try:
        async for token in llm.generate(messages):
            yield f"data: {json.dumps({'content': token})}\n\n"
        yield "data: [DONE]\n\n"
    except Exception as e:
        yield f"data: {json.dumps({'error': str(e)})}\n\n"
```

### ❌ 陷阱 5：客户端断开后服务端继续生成

```python
# ❌ 错误：客户端取消后，GPU 仍在生成 Token（浪费资源）

# ✅ 正确：检测客户端断开，取消 LLM 生成
@app.post("/chat")
async def chat(request: Request):
    async def stream():
        async for token in llm.generate_stream(messages):
            if await request.is_disconnected():
                break  # 客户端已断开，停止生成
            yield f"data: {json.dumps({'content': token})}\n\n"
    return StreamingResponse(stream(), ...)
```

## 10. 延伸与前沿

### 10.1 HTTP/2 Server Push 与 SSE

HTTP/2 的多路复用解决了 HTTP/1.1 的 6 连接限制问题，SSE 在 HTTP/2 下可以并行打开更多流。

### 10.2 WebTransport

WebTransport 是下一代传输协议（基于 HTTP/3 QUIC），支持：
- 可靠和不可靠的数据传输
- 多流复用
- 比 WebSocket 更低的延迟
- 未来可能替代 SSE + WebSocket

### 10.3 实时语音 AI

OpenAI Realtime API 使用 WebSocket 实现双向语音流：
- 上行：音频流（用户说话）
- 下行：音频流（AI 回复） + 文本流（转录）
- 这是 WebSocket 的正确使用场景——真正的双向实时通信

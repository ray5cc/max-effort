## 1. 整体架构分层

```
┌────────────────────────────────────────────────────────┐
│                   用户接口层（Python / Java / C++）        │
│  tf.keras │ tf.data │ tf.distribute │ tf.saved_model    │
├────────────────────────────────────────────────────────┤
│               高级 Python API（tf.* 命名空间）             │
│   自动微分（GradientTape）│ 函数追踪（@tf.function）         │
├────────────────────────────────────────────────────────┤
│                  C++ 运行时核心                            │
│  图执行引擎 │ Executor │ 设备管理 │ 内存分配 │ 通信原语      │
├────────────────────────────────────────────────────────┤
│                    Kernel 实现层                          │
│  CPU Kernels │ GPU Kernels (CUDA) │ TPU Kernels          │
│  cuDNN │ cuBLAS │ oneDNN │ XLA                           │
├────────────────────────────────────────────────────────┤
│                    硬件抽象层                              │
│       CPU    │    NVIDIA GPU    │  Google TPU  │  其他     │
└────────────────────────────────────────────────────────┘
```

### 各层职责

| 层级 | 职责 | 关键组件 |
|------|------|---------|
| 用户接口层 | 提供高层 API，屏蔽底层细节 | Keras、tf.data、tf.distribute |
| Python API 层 | 图构建、追踪、自动微分 | `@tf.function`、GradientTape |
| C++ 运行时 | 图调度、内存管理、多设备协调 | Executor、Rendezvous、Allocator |
| Kernel 实现 | 具体算子的硬件加速实现 | CUDA Kernels、XLA HLO |
| 硬件抽象层 | 统一硬件接口 | Device API、Stream Executor |

## 2. 计算图与执行引擎

### 2.1 计算图（DAG）结构

```
示例：y = ReLU(x @ W + b)

     x (Placeholder)    W (Variable)
          │                  │
          └──────┬───────────┘
                 ▼
            [MatMul Op]
                 │
                 ▼
     b ──→ [BiasAdd Op]
                 │
                 ▼
            [ReLU Op]
                 │
                 ▼
              y (Output)
```

每个节点（Op）包含：
- **名称（name）**：如 `"MatMul:0"`
- **类型（type）**：如 `MatMul`、`BiasAdd`、`Relu`
- **属性（attrs）**：如数据类型、维度
- **输入边列表**：指向前驱节点输出张量

### 2.2 图优化流程

```python
@tf.function
def my_fn(x):
    return tf.nn.relu(tf.matmul(x, w) + b)

# 调用时执行以下步骤：
# 1. Tracing（追踪）：将 Python 函数转换为 FuncGraph
# 2. Grappler 优化：
#    - 常量折叠（Constant Folding）
#    - 公共子表达式消除（CSE）
#    - 算子融合（Op Fusion）：MatMul + BiasAdd + Relu → FusedMatMul
# 3. （可选）XLA 编译：HLO 生成 → 硬件原生代码
# 4. 执行：调度到目标设备
```

### 2.3 设备放置（Device Placement）

```python
# 自动设备放置
with tf.device('/GPU:0'):
    a = tf.constant([[1.0, 2.0]])

with tf.device('/CPU:0'):
    b = tf.constant([[3.0], [4.0]])

# 跨设备操作（自动插入数据复制节点）
c = tf.matmul(a, b)

# 查看张量所在设备
print(c.device)  # /job:localhost/replica:0/task:0/device:GPU:0
```

### 2.4 Session 与 Eager 的对比（内部机制）

```
TF 1.x Session 模式：
  Python 侧          C++ 侧
  构建图 ──Proto──→  GraphDef
  sess.run() ─────→ Executor.Run()
                       │── 设备调度
                       │── Kernel 执行
                       └── 结果返回 Python

TF 2.x Eager 模式：
  Python 侧          C++ 侧
  tf.constant() ──→  EagerTensor（立即分配）
  tf.matmul() ────→  EagerExecute()（立即计算）
                       └── 结果立即返回

  @tf.function 追踪后：
  Python 函数 ──追踪──→ ConcreteFunction
              ──执行──→ FunctionLibraryRuntime
```

## 3. 核心 API 模块

### 3.1 tf.keras — 高级神经网络 API

Keras 提供三种模型构建方式：

#### Sequential API（顺序模型）

```python
model = tf.keras.Sequential([
    tf.keras.layers.Input(shape=(784,)),
    tf.keras.layers.Dense(256, activation='relu'),
    tf.keras.layers.Dropout(0.3),
    tf.keras.layers.Dense(128, activation='relu'),
    tf.keras.layers.Dense(10, activation='softmax')
])

model.compile(
    optimizer=tf.keras.optimizers.Adam(1e-3),
    loss='sparse_categorical_crossentropy',
    metrics=['accuracy']
)
model.summary()
```

#### Functional API（函数式模型）

```python
# 支持多输入/多输出、共享层、非线性拓扑
inputs = tf.keras.Input(shape=(784,))
x = tf.keras.layers.Dense(256, activation='relu')(inputs)
x = tf.keras.layers.Dropout(0.3)(x)
x = tf.keras.layers.Dense(128, activation='relu')(x)
outputs = tf.keras.layers.Dense(10, activation='softmax')(x)

model = tf.keras.Model(inputs=inputs, outputs=outputs)
```

#### Subclassing API（子类化模型）

```python
class MyModel(tf.keras.Model):
    def __init__(self):
        super().__init__()
        self.dense1 = tf.keras.layers.Dense(256, activation='relu')
        self.dropout = tf.keras.layers.Dropout(0.3)
        self.dense2 = tf.keras.layers.Dense(10, activation='softmax')

    def call(self, inputs, training=False):
        x = self.dense1(inputs)
        x = self.dropout(x, training=training)
        return self.dense2(x)

model = MyModel()
```

### 3.2 tf.data — 数据输入流水线

```python
# 高效数据流水线构建
dataset = tf.data.Dataset.from_tensor_slices((x_train, y_train))

dataset = (dataset
    .shuffle(buffer_size=10000)         # 随机打乱
    .batch(32)                          # 批次化
    .map(augment_fn,                    # 数据增强
         num_parallel_calls=tf.data.AUTOTUNE)
    .cache()                            # 缓存到内存/磁盘
    .prefetch(tf.data.AUTOTUNE)         # 预取，与 GPU 计算并行
)

# 从 TFRecord 文件构建数据集
raw_dataset = tf.data.TFRecordDataset(filenames)
parsed_dataset = raw_dataset.map(parse_tfrecord_fn)
```

#### tf.data 性能流水线

```
磁盘 I/O          CPU 预处理        GPU 训练
  │                   │                │
  ▼                   ▼                ▼
读取文件 ──→ 解码/增强/批次 ──→ 模型前向/反向
            （prefetch 使这两阶段并行）
```

## 4. TensorFlow Serving

TF Serving 是 TensorFlow 官方推理服务框架，专为**生产环境**设计。

### 架构概览

```
客户端                  TF Serving                  模型存储
  │                        │                            │
  ├── REST HTTP/1.1 ──→  REST API Server               │
  │   POST /v1/models/    │                             │
  │   :predict            │                             │
  │                       ├── Source (文件系统监控) ←── SavedModel
  ├── gRPC ───────────→  gRPC Server                    │
      PredictRequest       │                             │
                           ├── Model Manager             │
                           │   └── Version Policy        │
                           │       (Latest / Specific)   │
                           └── Servable (已加载模型实例)
```

### 核心组件

| 组件 | 职责 |
|------|------|
| **Source** | 监控文件系统/GCS/S3，检测模型版本变化 |
| **Loader** | 加载/卸载特定版本的 SavedModel |
| **Servable** | 已加载并可对外服务的模型实例 |
| **Manager** | 管理 Servable 生命周期和版本切换 |
| **Batcher** | 请求批次合并，提高 GPU 利用率 |

### 请求流程

```python
import requests
import json
import numpy as np

# REST API 请求示例
data = {
    "signature_name": "serving_default",
    "instances": [[1.0, 2.0, 3.0, 4.0]]  # 输入数据
}

response = requests.post(
    'http://localhost:8501/v1/models/my_model:predict',
    json=data
)
result = response.json()
print(result['predictions'])
```

## 5. TensorFlow Lite

TFLite 是面向**移动端和嵌入式设备**的轻量级推理框架。

### 转换流程

```
TF SavedModel / Keras Model
          │
    TFLiteConverter
    ├── 算子选择与简化
    ├── 量化（可选）
    │   ├── 动态范围量化（权重 INT8）
    │   ├── 全整数量化（权重+激活 INT8）
    │   └── Float16 量化
    └── FlatBuffers 序列化
          │
     .tflite 文件
          │
   ┌──────┼──────────┐
   ▼      ▼          ▼
Android  iOS    嵌入式（C API）
```

### 模型转换代码

```python
import tensorflow as tf

# 方式 1：从 SavedModel 转换
converter = tf.lite.TFLiteConverter.from_saved_model('saved_model_dir')

# 方式 2：从 Keras 模型转换
converter = tf.lite.TFLiteConverter.from_keras_model(model)

# 全整数量化（需要代表性数据集）
def representative_dataset():
    for data in tf.data.Dataset.from_tensor_slices(x_test).batch(1).take(100):
        yield [tf.cast(data, tf.float32)]

converter.optimizations = [tf.lite.Optimize.DEFAULT]
converter.representative_dataset = representative_dataset
converter.target_spec.supported_ops = [tf.lite.OpsSet.TFLITE_BUILTINS_INT8]
converter.inference_input_type = tf.int8
converter.inference_output_type = tf.int8

tflite_model = converter.convert()
with open('model_quant.tflite', 'wb') as f:
    f.write(tflite_model)

# Python 推理
interpreter = tf.lite.Interpreter(model_path='model_quant.tflite')
interpreter.allocate_tensors()

input_details = interpreter.get_input_details()
output_details = interpreter.get_output_details()

interpreter.set_tensor(input_details[0]['index'], input_data)
interpreter.invoke()
output = interpreter.get_tensor(output_details[0]['index'])
```

### 量化效果对比

| 量化方式 | 模型大小 | 延迟 | 精度损失 | 适用场景 |
|---------|---------|------|---------|---------|
| FP32（无量化） | 100% | 100% | 0 | 服务器推理 |
| FP16 量化 | ~50% | ~60% | 极小 | GPU 移动端 |
| 动态范围量化 | ~25% | ~75% | 小 | CPU 移动端 |
| 全整数量化（INT8） | ~25% | ~50% | 小~中 | MCU/DSP |

## 6. TensorFlow.js

TF.js 使 JavaScript 环境（浏览器 / Node.js）能够运行 TensorFlow 模型。

### 架构层次

```
JavaScript API（tf.* 高层 API）
        │
  后端选择（Backend）
  ├── WebGL 后端    → GPU 加速（浏览器）
  ├── WASM 后端     → CPU 优化（浏览器/Node.js）
  └── Node.js 后端  → 调用 TF C++ 库（服务端）
```

```javascript
// 模型转换：Python TF → TF.js
// tensorflowjs_converter --input_format=tf_saved_model \
//   --output_node_names='output' \
//   saved_model_dir/ tfjs_model/

const model = await tf.loadLayersModel('tfjs_model/model.json');

const input = tf.tensor2d([[1, 2, 3, 4]], [1, 4]);
const prediction = model.predict(input);
prediction.print();
```

## 7. TensorBoard

TensorBoard 是 TensorFlow 的可视化工具，提供训练过程的全方位洞察。

### 主要功能模块

| 功能板 | 内容 | API |
|-------|------|-----|
| **Scalars** | loss、accuracy 曲线 | `tf.summary.scalar()` |
| **Graphs** | 计算图结构可视化 | 自动捕获 |
| **Histograms** | 权重/梯度分布 | `tf.summary.histogram()` |
| **Images** | 图像样本可视化 | `tf.summary.image()` |
| **Profile** | 性能分析（GPU 利用率/算子耗时） | `tf.profiler` |
| **Projector** | 高维嵌入向量 t-SNE 可视化 | Embedding Projector |
| **HParams** | 超参数对比实验 | `tensorboard.plugins.hparams` |

### 使用示例

```python
import datetime

log_dir = "logs/fit/" + datetime.datetime.now().strftime("%Y%m%d-%H%M%S")
tensorboard_callback = tf.keras.callbacks.TensorBoard(
    log_dir=log_dir,
    histogram_freq=1,       # 每 epoch 记录权重直方图
    profile_batch='10,20'   # 对第 10-20 个 batch 做 profiling
)

model.fit(
    train_dataset,
    epochs=20,
    validation_data=val_dataset,
    callbacks=[tensorboard_callback]
)

# 自定义 Summary
writer = tf.summary.create_file_writer(log_dir)
with writer.as_default():
    for step, (x, y) in enumerate(train_dataset):
        loss = train_step(x, y)
        tf.summary.scalar('custom_loss', loss, step=step)
```

## 8. XLA 编译器

XLA（Accelerated Linear Algebra）是 TensorFlow 的领域专用编译器，通过图级别优化提升执行性能。

### 编译流程

```
TF 计算图（tf.Graph）
        │
  HLO（High-Level Operations）生成
  ├── 算子规范化
  └── 内联展开
        │
  HLO 优化 Pass
  ├── 算子融合（Fusion）：将多个小算子合并成一个 Kernel
  ├── 缓冲区分析（Buffer Assignment）：最小化内存分配
  ├── 循环展开（Loop Unrolling）
  └── 常量传播（Constant Propagation）
        │
  LLO（Low-Level Operations）代码生成
  ├── CPU → LLVM IR → 机器码
  ├── GPU → PTX → CUBIN
  └── TPU → TPU 固件指令
```

### 启用 XLA

```python
# 方式 1：全局启用（所有 @tf.function）
tf.config.optimizer.set_jit(True)

# 方式 2：单函数启用
@tf.function(jit_compile=True)
def compute(x, y):
    return tf.reduce_sum(x * y)

# 方式 3：环境变量
# TF_XLA_FLAGS=--tf_xla_auto_jit=2

# XLA 主要优化收益：
# - 算子融合减少内存带宽瓶颈
# - 减少 Kernel launch 开销
# - 消除中间结果的内存分配
# 典型加速比：1.2x - 3x（依模型结构而异）
```

### XLA vs cuDNN 的关系

```
cuDNN：NVIDIA 提供的手工优化 Kernel 库
  - 针对特定算子（Conv、GEMM、RNN）高度优化
  - 适合标准模型结构

XLA：通用编译器优化
  - 对自定义计算图更灵活
  - 通过融合减少访存开销
  - 在 TPU 上尤其重要（TPU 没有 cuDNN）

TF 的选择策略：
  标准层（Conv2D、Dense）→ 优先用 cuDNN
  自定义/融合场景 → XLA 更有优势
```

## 总结

TensorFlow 的架构从底层 Kernel 实现到高层 Keras API，形成了清晰的分层体系。其中 XLA 负责编译优化、TF Serving 负责生产部署、TFLite 负责边缘推理、TF.js 负责浏览器端推理，各子系统协同构成完整的端到端 ML 基础设施。

## 1. SSE 与 Fetch Streaming

### 1.1 EventSource API 状态机

浏览器原生 `EventSource` 维护一个简单的三态状态机：

```
          new EventSource(url)
                  │
                  ▼
           CONNECTING (0)
          /       │      \
    网络错误    连接成功    手动 .close()
       │           │           │
       ▼           ▼           ▼
  CONNECTING(0)  OPEN (1)   CLOSED (2)
  (自动重试)      │
              服务端关闭
              或网络中断
                  │
                  ▼
           CONNECTING (0)
           (Last-Event-ID
            自动重连)
```

```typescript
const es = new EventSource("/v1/chat/stream?session=abc");

// readyState: 0=CONNECTING, 1=OPEN, 2=CLOSED
console.log(es.readyState);

es.addEventListener("message", (e) => {
  const data = JSON.parse(e.data);
  console.log("token:", data.delta);
});

es.addEventListener("error", (e) => {
  if (es.readyState === EventSource.CLOSED) {
    console.log("Stream closed by server");
  } else {
    console.warn("Connection error, auto-retrying...");
  }
});

// EventSource 不支持 POST，需要自定义事件类型传参
es.addEventListener("done", () => es.close());
```

> **EventSource 局限**：只支持 GET 请求，不能发送 JSON Body。AI Chat 场景的消息体较大，通常改用 Fetch Streaming。

### 1.2 Fetch Streaming 完整 TypeScript 实现

```typescript
interface StreamOptions {
  messages: { role: string; content: string }[];
  model?: string;
  signal?: AbortSignal;
  onToken?: (token: string) => void;
  onError?: (error: Error) => void;
  onComplete?: (fullText: string) => void;
}

async function fetchStream({
  messages,
  model = "gpt-4o-mini",
  signal,
  onToken,
  onError,
  onComplete,
}: StreamOptions): Promise<void> {
  let response: Response;

  try {
    response = await fetch("/v1/chat/stream", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Accept: "text/event-stream",
      },
      body: JSON.stringify({ messages, model }),
      signal,
    });
  } catch (err) {
    onError?.(err instanceof Error ? err : new Error(String(err)));
    return;
  }

  if (!response.ok) {
    onError?.(new Error(`HTTP ${response.status}: ${response.statusText}`));
    return;
  }

  if (!response.body) {
    onError?.(new Error("ReadableStream not supported"));
    return;
  }

  const reader = response.body.getReader();
  const decoder = new TextDecoder("utf-8");
  let buffer = "";
  let fullText = "";

  try {
    while (true) {
      const { done, value } = await reader.read();

      if (done) break;

      // stream: true 告诉 TextDecoder 保留多字节字符的未完成字节
      buffer += decoder.decode(value, { stream: true });

      // 按换行分割，处理完整的 SSE 行
      const lines = buffer.split("\n");

      // 最后一个元素可能是不完整的行，保留到下次
      buffer = lines.pop() ?? "";

      for (const line of lines) {
        const trimmed = line.trim();
        if (!trimmed || !trimmed.startsWith("data: ")) continue;

        const payload = trimmed.slice(6);

        if (payload === "[DONE]") {
          onComplete?.(fullText);
          return;
        }

        try {
          const parsed = JSON.parse(payload) as { delta?: string; error?: string };

          if (parsed.error) {
            onError?.(new Error(parsed.error));
            return;
          }

          if (parsed.delta) {
            fullText += parsed.delta;
            onToken?.(parsed.delta);
          }
        } catch {
          // 跳过无法解析的行（心跳包等）
        }
      }
    }

    // 处理 buffer 中剩余内容（无 [DONE] 结尾时）
    onComplete?.(fullText);
  } catch (err) {
    if (signal?.aborted) return; // 用户主动取消，不视为错误
    onError?.(err instanceof Error ? err : new Error(String(err)));
  } finally {
    reader.cancel();
  }
}


// 使用示例
const controller = new AbortController();

fetchStream({
  messages: [{ role: "user", content: "解释量子纠缠" }],
  signal: controller.signal,
  onToken: (token) => process.stdout.write(token),
  onComplete: (text) => console.log("\n✅ Done:", text.length, "chars"),
  onError: (err) => console.error("❌ Error:", err.message),
});

// 5 秒后取消
setTimeout(() => controller.abort(), 5000);
```

### 1.3 SSE vs WebSocket 选择矩阵

| 维度 | SSE（Fetch Streaming） | WebSocket |
|------|------------------------|-----------|
| **通信方向** | 单向（服务端 → 客户端） | 全双工 |
| **协议** | HTTP/1.1 or HTTP/2 | WS/WSS（独立协议） |
| **基础设施兼容** | 天然穿透代理、CDN、负载均衡 | 需要特殊配置支持 |
| **自动重连** | EventSource 内置；Fetch 需手动 | 需手动实现 |
| **发送消息 Body** | POST + JSON（Fetch方式） | 任意时刻双向发送 |
| **打字机中断** | 需关闭连接重开 | 可直接发 stop 消息 |
| **适合场景** | 单次流式问答 | 多轮实时交互、语音 |
| **实现复杂度** | 低 | 中等 |

**推荐策略**：默认使用 Fetch Streaming（SSE），仅当需要双向实时通信（如语音对话、Agent 工具调用中断）时升级到 WebSocket。

```typescript
import { useState, useTransition, useDeferredValue } from "react";

function StreamingChat() {
  const [content, setContent] = useState("");
  const [isPending, startTransition] = useTransition();

  // useDeferredValue：对 Markdown 渲染使用低优先级更新
  // 保证输入框响应不被 Markdown 重渲染阻塞
  const deferredContent = useDeferredValue(content);

  const handleStream = async (query: string) => {
    setContent(""); // 清空上一轮

      messages: [{ role: "user", content: query }],
      onToken: (token) => {
        // startTransition 标记为低优先级，不阻塞用户交互
        startTransition(() => {
          setContent((prev) => prev + token);
        });
      },
    });
  };

  return (
    <div>
      <MarkdownRenderer content={deferredContent} />
      {isPending && <span className="cursor-blink">▌</span>}
    </div>
  );
```

## 3. Vercel AI SDK 核心接口

### 3.1 useChat Hook 内部状态机

```typescript
// useChat 简化实现，揭示其内部逻辑
import { useState, useCallback, useRef } from "react";

interface Message {
  id: string;
  role: "user" | "assistant";
  content: string;
}

type Status = "idle" | "loading" | "streaming" | "error";

function useChat({ api = "/api/chat" } = {}) {
  const [messages, setMessages] = useState<Message[]>([]);
  const [input, setInput] = useState("");
  const [status, setStatus] = useState<Status>("idle");
  const [error, setError] = useState<Error | null>(null);
  const abortControllerRef = useRef<AbortController | null>(null);

  const append = useCallback(
    async (userMessage: { role: "user"; content: string }) => {
      const userMsg: Message = {
        id: crypto.randomUUID(),
        ...userMessage,
      };

      // 乐观更新：立即显示用户消息
      setMessages((prev) => [...prev, userMsg]);
      setStatus("loading");
      setError(null);

      // 创建占位符 assistant 消息
      const assistantId = crypto.randomUUID();
      setMessages((prev) => [
        ...prev,
        { id: assistantId, role: "assistant", content: "" },
      ]);

      abortControllerRef.current = new AbortController();

      try {
        await fetchStream({
          messages: [...messages, userMsg].map(({ role, content }) => ({
            role,
            content,
          })),
          signal: abortControllerRef.current.signal,
          onToken: (token) => {
            setStatus("streaming");
            // 函数式更新，精确定位 assistant 占位符
            setMessages((prev) =>
              prev.map((msg) =>
                msg.id === assistantId
                  ? { ...msg, content: msg.content + token }
                  : msg
              )
            );
          },
          onComplete: () => setStatus("idle"),
          onError: (err) => {
            setStatus("error");
            setError(err);
            // 移除空的 assistant 占位符
            setMessages((prev) => prev.filter((m) => m.id !== assistantId));
          },
        });
      } catch (err) {
        if ((err as Error).name !== "AbortError") {
          setStatus("error");
        }
      }
    },
    [messages]
  );

  const handleSubmit = useCallback(
    (e: React.FormEvent) => {
      e.preventDefault();
      if (!input.trim() || status === "streaming") return;
      append({ role: "user", content: input });
      setInput("");
    },
    [input, status, append]
  );

  const stop = useCallback(() => {
    abortControllerRef.current?.abort();
    setStatus("idle");
  }, []);

  const reload = useCallback(() => {
    // 重新发送最后一条用户消息
    const lastUserMsg = [...messages].reverse().find((m) => m.role === "user");
    if (lastUserMsg) {
      setMessages((prev) => prev.slice(0, -2)); // 移除最后一轮
      append({ role: "user", content: lastUserMsg.content });
    }
  }, [messages, append]);

  return {
    messages,
    input,
    setInput,
    status,
    error,
    isLoading: status === "loading" || status === "streaming",
    handleSubmit,
    append,
    stop,
    reload,
  };
}
```

### 3.2 Vercel AI SDK 数据流协议

AI SDK 定义了一套文本协议，在 SSE 的 `data:` 字段中传递结构化信息：

```
# type 0 — 文本 delta（最常见）
data: 0:"Hello"
data: 0:" World"

# type 2 — 数据（工具调用结果，JSON 数组）
data: 2:[{"tool":"search","result":"..."}]

# type a — 工具调用（tool_use）
data: a:{"toolCallId":"tc_1","toolName":"search","args":{"q":"react"}}

# type d — 完成信号（带 usage 信息）
data: d:{"finishReason":"stop","usage":{"promptTokens":120,"completionTokens":45}}
```

```typescript
// 解析 AI SDK 数据流协议
function parseAIStreamChunk(line: string): void {
  if (!line.startsWith("data: ")) return;
  const payload = line.slice(6);
  if (payload === "[DONE]") return;

  // 格式: <type>:<json_encoded_value>
  const colonIdx = payload.indexOf(":");
  if (colonIdx === -1) return;

  const type = payload.slice(0, colonIdx);
  const value = JSON.parse(payload.slice(colonIdx + 1));

  switch (type) {
    case "0": // text delta
      appendToMessage(value as string);
      break;
    case "2": // data parts
      handleDataParts(value as unknown[]);
      break;
    case "a": // tool call
      handleToolCall(value as ToolCall);
      break;
    case "d": // finish
      handleFinish(value as FinishData);
      break;
  }
}
```

## 4. Markdown 实时渲染与性能优化

### 4.1 react-markdown 插件组合

```typescript
import ReactMarkdown from "react-markdown";
import remarkGfm from "remark-gfm";           // GitHub Flavored Markdown（表格、任务列表）
import remarkMath from "remark-math";          // LaTeX 数学公式

  isTrusted?: boolean; // 来自 LLM 的内容是否需要净化

function MarkdownRenderer({ content, isTrusted = false }: MarkdownProps) {
  const rehypePlugins = [
    rehypeHighlight,
    rehypeKatex,
    // 用户输入的内容务必净化；LLM 输出可选（LLM 一般不生成恶意 HTML）

        // 外部链接新标签页打开

          const isExternal = href?.startsWith("http");
          return (
            <a
              href={href}
              target={isExternal ? "_blank" : undefined}
              rel={isExternal ? "noopener noreferrer" : undefined}
            >
              {children}
            </a>
          );
        },
      }}
    >
      {content}
    </ReactMarkdown>
  );
}
```

### 4.2 rAF 批量更新优化

每个 Token 到来时直接调用 `setState` 会导致每秒 30~60 次重渲染，包含 Markdown 解析的话性能压力极大：

```typescript
import { useRef, useState, useEffect, useCallback } from "react";

function useTokenBuffer(onFlush: (text: string) => void) {
  const bufferRef = useRef<string[]>([]);
  const rafRef = useRef<number>(0);

  const addToken = useCallback(
    (token: string) => {
      bufferRef.current.push(token);

      // 若已有 RAF 在等待，不重复调度
      if (rafRef.current) return;

      rafRef.current = requestAnimationFrame(() => {
        // 在下一帧统一 flush，合并同一帧内的所有 token
        const batch = bufferRef.current.join("");
        bufferRef.current = [];
        rafRef.current = 0;
        if (batch) onFlush(batch);
      });
    },
    [onFlush]
  );

  // 组件卸载时取消待执行的 RAF
  useEffect(
    () => () => {
      if (rafRef.current) cancelAnimationFrame(rafRef.current);
    },
    []
  );

  return addToken;
}

// 集成到 Chat 组件
function OptimizedChat() {
  const [displayContent, setDisplayContent] = useState("");

  const addToken = useTokenBuffer((batch) => {
    setDisplayContent((prev) => prev + batch);
  });

  return (
    <div>
      <MarkdownRenderer content={displayContent} />
    </div>
  );
}
```

### 4.3 useRef 字符队列打字机效果

纯 CSS 动画打字机效果在流式场景会失效（内容动态追加），需要用 JS 实现平滑的逐字显示：

```typescript
import { useState, useRef, useEffect } from "react";

interface TypewriterOptions {
  speed?: number;       // 字符/帧，默认 2
  maxQueueSize?: number; // 防止 buffer 无限增长
}

function useTypewriter({ speed = 2, maxQueueSize = 500 }: TypewriterOptions = {}) {
  const [displayed, setDisplayed] = useState("");
  const queueRef = useRef<string[]>([]);   // 待渲染字符队列
  const rafRef = useRef<number>(0);
  const isRunningRef = useRef(false);

  const startLoop = useCallback(() => {
    if (isRunningRef.current) return;
    isRunningRef.current = true;

    const tick = () => {
      if (queueRef.current.length === 0) {
        isRunningRef.current = false;
        return;
      }

      // 每帧取出 speed 个字符
      const chars = queueRef.current.splice(0, speed);
      setDisplayed((prev) => prev + chars.join(""));

      rafRef.current = requestAnimationFrame(tick);
    };

    rafRef.current = requestAnimationFrame(tick);
  }, [speed]);

  const pushChars = useCallback(
    (text: string) => {
      // 防溢出：超出最大队列直接追加，避免追不上的情况
      if (queueRef.current.length > maxQueueSize) {
        setDisplayed((prev) => prev + text);
        return;
      }
      queueRef.current.push(...text.split(""));
      startLoop();
    },
    [maxQueueSize, startLoop]
  );

  const reset = useCallback(() => {
    if (rafRef.current) cancelAnimationFrame(rafRef.current);
    queueRef.current = [];
    isRunningRef.current = false;
    setDisplayed("");
  }, []);

  useEffect(() => () => {
    if (rafRef.current) cancelAnimationFrame(rafRef.current);
  }, []);

  return { displayed, pushChars, reset, isPending: queueRef.current.length > 0 };
}

// 使用
function TypewriterMessage({ onToken }: { onToken: () => void }) {
  const { displayed, pushChars, reset } = useTypewriter({ speed: 3 });

  return <MarkdownRenderer content={displayed} />;
}
```

### 5.1 消息状态机

每条 AI 消息经历完整的生命周期：

```
                    用户提交
                      │
                      ▼
                  ┌─────────┐
                  │ pending │  等待首字节（TTFT）
                  └────┬────┘
                       │ 首个 token 到达
                       ▼
                 ┌───────────┐
                 │ streaming │  逐 token 追加
                 └─────┬─────┘
                       │
           ┌───────────┴───────────┐
           │ [DONE] 或流结束        │ 网络错误 / 超时
           ▼                       ▼
      ┌──────────┐            ┌─────────┐
      │ complete │            │  error  │
      └──────────┘            └────┬────┘
                                   │ 点击重试
                                   ▼
                               ┌─────────┐
                               │ pending │
                               └─────────┘
```

```typescript
function MessageBubble({ message }: { message: ChatMessage }) {

        {message.status === "pending" && (
          <div className="flex gap-1">
            {[0, 1, 2].map((i) => (
              <div
                key={i}
                className="w-2 h-2 bg-gray-400 rounded-full animate-bounce"
                style={{ animationDelay: `${i * 0.15}s` }}
              />
            ))}
          </div>
        )}

        {/* 流式 / 完成状态 */}
        {(message.status === "streaming" || message.status === "complete") && (
          <>
            <MarkdownRenderer content={message.content} />
            {message.status === "streaming" && (
              <span className="inline-block w-0.5 h-4 bg-current animate-blink ml-0.5" />
            )}
          </>
        )}

        {/* 错误状态 */}
        {message.status === "error" && (
          <div className="text-red-500">
            <p>出错了：{message.error}</p>
            <button
              className="mt-2 text-sm underline"
              onClick={() => retryMessage(message.id)}
            >
              重试
            </button>
          </div>
        )}
      </div>
    </div>
  );
}
```

### 5.2 Auto-scroll 吸底逻辑

```typescript
import { useRef, useEffect, useCallback, useState } from "react";

function useAutoScroll(dependency: unknown) {
  const containerRef = useRef<HTMLDivElement>(null);
  const [isAtBottom, setIsAtBottom] = useState(true);
  const userScrolledUpRef = useRef(false);

  // 检测用户是否手动滚动离开底部
  const handleScroll = useCallback(() => {
    const el = containerRef.current;
    if (!el) return;

    // 距离底部 50px 以内视为"在底部"
    const threshold = 50;
    const atBottom =
      el.scrollHeight - el.scrollTop - el.clientHeight <= threshold;

    setIsAtBottom(atBottom);
    userScrolledUpRef.current = !atBottom;
  }, []);

  const scrollToBottom = useCallback((behavior: ScrollBehavior = "smooth") => {
    const el = containerRef.current;
    if (!el) return;
    el.scrollTo({ top: el.scrollHeight, behavior });
  }, []);

  // 内容变化时，若用户未手动上滚则自动吸底
  useEffect(() => {
    if (!userScrolledUpRef.current) {
      scrollToBottom("smooth");
    }
  }, [dependency, scrollToBottom]);

  // 流式开始时强制吸底（新消息出现）
  const onStreamStart = useCallback(() => {
    userScrolledUpRef.current = false;
    scrollToBottom("instant");
  }, [scrollToBottom]);

  return {
    containerRef,
    isAtBottom,
    scrollToBottom,
    onStreamStart,
    handleScroll,
  };
}

// 消息列表组件
function MessageList({ messages }: { messages: ChatMessage[] }) {
  const lastMessage = messages[messages.length - 1];

    useAutoScroll(lastMessage?.content);
```

### 6.1 Zustand Chat Store 设计

```typescript
import { create } from "zustand";
import { immer } from "zustand/middleware/immer";
import { persist } from "zustand/middleware";

interface ChatStore {
  // 状态
  sessions: Record<string, ChatSession>;
  activeSessionId: string | null;
  isStreaming: boolean;

  // 派生数据（getter）
  activeSession: () => ChatSession | null;

  // 操作
  createSession: () => string;
  deleteSession: (id: string) => void;
  setActiveSession: (id: string) => void;
  addMessage: (sessionId: string, message: ChatMessage) => void;
  updateLastAssistantMessage: (sessionId: string, delta: string) => void;
  finalizeMessage: (sessionId: string, status: "complete" | "error", error?: string) => void;
  setStreaming: (value: boolean) => void;
  clearSession: (sessionId: string) => void;
}

const useChatStore = create<ChatStore>()(
  persist(
    immer((set, get) => ({
      sessions: {},
      activeSessionId: null,
      isStreaming: false,

      activeSession: () => {
        const { sessions, activeSessionId } = get();
        return activeSessionId ? (sessions[activeSessionId] ?? null) : null;
      },

      createSession: () => {
        const id = crypto.randomUUID();
        set((state) => {
          state.sessions[id] = {
            id,
            title: "新对话",
            messages: [],
            createdAt: Date.now(),
            updatedAt: Date.now(),
          };
          state.activeSessionId = id;
        });
        return id;
      },

      deleteSession: (id) => {
        set((state) => {
          delete state.sessions[id];
          if (state.activeSessionId === id) {
            const ids = Object.keys(state.sessions);
            state.activeSessionId = ids[ids.length - 1] ?? null;
          }
        });
      },

      setActiveSession: (id) => set({ activeSessionId: id }),

      addMessage: (sessionId, message) => {
        set((state) => {
          const session = state.sessions[sessionId];
          if (session) {
            session.messages.push(message);
            session.updatedAt = Date.now();
            // 自动从第一条用户消息生成标题
            if (session.title === "新对话" && message.role === "user") {
              session.title = message.content.slice(0, 30) + (message.content.length > 30 ? "…" : "");
            }
          }
        });
      },

      updateLastAssistantMessage: (sessionId, delta) => {
        set((state) => {
          const session = state.sessions[sessionId];
          if (!session) return;
          const msgs = session.messages;
          const last = msgs[msgs.length - 1];
          if (last?.role === "assistant") {
            last.content += delta;
            last.status = "streaming";
          }
        });
      },

      finalizeMessage: (sessionId, status, error) => {
        set((state) => {
          const session = state.sessions[sessionId];
          if (!session) return;
          const msgs = session.messages;
          const last = msgs[msgs.length - 1];
          if (last?.role === "assistant") {
            last.status = status;
            if (error) last.error = error;
          }
        });
      },

      setStreaming: (value) => set({ isStreaming: value }),

      clearSession: (sessionId) => {
        set((state) => {
          const session = state.sessions[sessionId];
          if (session) {
            session.messages = [];
            session.updatedAt = Date.now();
          }
        });
      },
    })),
    {
      name: "chat-store",
      // 只持久化会话列表，不持久化 isStreaming 等运行时状态
      partialize: (state) => ({
        sessions: state.sessions,
        activeSessionId: state.activeSessionId,
      }),
    }
  )
);

export default useChatStore;
```

```typescript
// hooks/useMarkdownWorker.ts
import { useRef, useCallback } from "react";

type Resolve = (html: string) => void;

export function useMarkdownWorker() {
  const workerRef = useRef<Worker | null>(null);
  const pendingRef = useRef<Map<string, Resolve>>(new Map());

  const getWorker = useCallback(() => {
    if (!workerRef.current) {
      workerRef.current = new Worker(
        new URL("../workers/markdown.worker.ts", import.meta.url),
        { type: "module" }
      );
      workerRef.current.addEventListener("message", (e) => {
        const { id, html, error } = e.data;
        const resolve = pendingRef.current.get(id);
        if (resolve) {
          pendingRef.current.delete(id);
          resolve(error ? `<p>渲染出错</p>` : html);
        }
      });
    }
    return workerRef.current;
  }, []);

  const parseMarkdown = useCallback(
    (markdown: string): Promise<string> => {
      return new Promise((resolve) => {
        const id = crypto.randomUUID();
        pendingRef.current.set(id, resolve);
        getWorker().postMessage({ id, markdown });
      });
    },
    [getWorker]
  );

  return { parseMarkdown };
}
```

## 7. AG-UI Protocol — Agent-User 交互协议

### 7.1 为什么需要 AG-UI？

想象一下你装修房子。水电工、瓦工、木工各有专长（就像 AI Agent 各有能力），但他们和你（房主/用户）之间的沟通方式却完全不同——有人打电话、有人发微信、有人留纸条。如果有一个「统一的装修沟通协议」，规定所有工匠都通过同一个 App 与你实时沟通进度、请求确认、展示方案，那你的体验会好得多。

**AG-UI（Agent-User Interaction Protocol）就是这个"统一沟通协议"——它标准化了 AI Agent 与前端 UI 之间的交互方式。**

在 2026 年之前，AI 前端面临一个核心困境：

```
问题：每个 Agent 框架都有自己的 UI 集成方式

LangGraph Agent → 自定义 WebSocket 协议 → 自建前端
CrewAI Agent   → 自定义 REST API     → 自建前端
AutoGen Agent  → 自定义事件格式       → 自建前端

结果：同一个前端无法同时对接多个 Agent 框架
```

这就像 HTTP 出现之前，每个网站用不同的通信协议——浏览器根本无法通用。

### 7.2 AG-UI 在协议生态中的位置

AG-UI 与其他两大 AI 协议形成互补关系：

```
┌──────────────────────────────────────────────────────────┐
│                     AI 协议三件套                         │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  MCP (Model Context Protocol)                           │
│  ├── 用途：Agent ↔ 工具/数据源                           │
│  └── 类比：USB 接口（连接外设）                           │
│                                                          │
│  A2A (Agent-to-Agent Protocol)                          │
│  ├── 用途：Agent ↔ Agent                                │
│  └── 类比：对讲机（同事间沟通）                           │

│                 其他 Agent                                │
└──────────────────────────────────────────────────────────┘
```

### 7.3 核心概念：事件驱动架构

AG-UI 的设计哲学是**事件流**——Agent 的所有行为都表达为一系列标准化事件，UI 只需监听和渲染这些事件。

#### ~16 种标准事件类型

```typescript
// AG-UI 核心事件类型（精简示意）
type AGUIEventType =
  // === 生命周期事件 ===
  | "RUN_STARTED"        // Agent 开始执行
  | "RUN_FINISHED"       // Agent 完成执行
  | "RUN_ERROR"          // Agent 执行出错
  // === 文本流事件 ===
  | "TEXT_MESSAGE_START"  // 开始输出文本消息
  | "TEXT_MESSAGE_CONTENT"// 文本内容增量（逐 Token）
  | "TEXT_MESSAGE_END"    // 文本消息结束
  // === 工具调用事件 ===
  | "TOOL_CALL_START"    // 开始调用工具
  | "TOOL_CALL_ARGS"     // 工具参数增量
  | "TOOL_CALL_END"      // 工具调用结束
  // === 状态同步事件 ===
  | "STATE_SNAPSHOT"     // 完整状态快照
  | "STATE_DELTA"        // 增量状态更新（JSON Patch）
  // === 自定义事件 ===
  | "CUSTOM"             // 自定义扩展事件
  // === 步骤事件 ===
  | "STEP_STARTED"       // 推理步骤开始
  | "STEP_FINISHED"      // 推理步骤完成
  // === 消息元数据 ===
  | "RAW_MESSAGE_START"  // 原始消息开始
  | "RAW_MESSAGE_END";   // 原始消息结束
```

生活化类比：AG-UI 事件就像**餐厅点餐系统的状态推送**——从"已接单"（RUN_STARTED）→"正在烹饪"（TEXT_MESSAGE_CONTENT 逐步输出）→"呼叫服务员核实"（TOOL_CALL_START 触发 HITL）→"上菜"（RUN_FINISHED）。你在手机上实时看到每个环节的进度，而不是等 30 分钟后才知道菜好没好。

AG-UI 不绑定特定传输方式，支持多种传输层：

| 传输方式 | 适用场景 | 特点 |
|----------|----------|------|
| **SSE** | 最常见，Web 应用 | 单向推送，HTTP 兼容，自动重连 |
| **WebSocket** | 需要高频双向通信 | 全双工，延迟更低 |
| **Webhook** | 异步长任务 | Agent 完成后回调通知 |

想象你要开一家多品牌汽车维修店。每个品牌的诊断接口、零件规格、通信协议都不同——BMW 用 ISTA、奔驰用 XENTRY、丰田用 Techstream。如果有一个**通用诊断平台**，能用同一套接口连接所有品牌，你的维修效率会指数级提升。

**Vercel AI SDK 就是 AI 模型的"通用诊断平台"——一套 TypeScript API，统一对接 100+ 模型提供商。**

```
传统方式（每个提供商不同 API）：

OpenAI    → openai.chat.completions.create()
Anthropic → anthropic.messages.create()
Google    → google.generateContent()
...每换一个模型就要改代码

AI SDK 方式（统一 API）：

import { generateText } from "ai";
// 只需换 model 参数，其他代码完全不变
const result = await generateText({
  model: openai("gpt-4o"),      // 或 anthropic("claude-4-sonnet")
  prompt: "解释量子计算",        // 或 google("gemini-2.5-pro")
});
```

### 8.2 统一 Provider 架构

AI SDK 的核心设计是 **Provider 模式**——每个模型提供商实现同一个接口：

```typescript
import { openai } from "@ai-sdk/openai";
import { anthropic } from "@ai-sdk/anthropic";
import { google } from "@ai-sdk/google";
import { createOpenAICompatible } from "@ai-sdk/openai-compatible";

// 甚至可以连接自部署模型
const localLlama = createOpenAICompatible({
  baseURL: "http://localhost:11434/v1",
  name: "ollama",
});

// 所有 provider 使用完全相同的调用方式
const result = await generateText({
  model: openai("gpt-4o"),  // 随时可换成 anthropic("claude-4-sonnet")
  messages: [
    { role: "user", content: "解释 React Fiber 架构" }
  ],
});
```

**Vercel AI Gateway**：AI SDK 还支持通过 Vercel 的 AI Gateway 路由请求，无需自行管理各提供商的 API 密钥：

```typescript
import { gateway } from "@ai-sdk/gateway";

// 通过 Gateway 路由到最优模型
const result = await generateText({
  model: gateway("fast-model"),  // Gateway 自动选择最低延迟的模型
  prompt: "总结这篇文章",

```

### 8.3 Agent 循环：ToolLoopAgent

2026 年的 AI SDK 引入了成熟的 Agent 循环机制——Agent 可以自主调用工具、观察结果、决定下一步：

```typescript
import { agent, toolLoopAgent } from "ai";
import { openai } from "@ai-sdk/openai";
import { z } from "zod";

// 定义工具（Agent 可调用的能力）
const searchTool = {
  description: "搜索知识库",
  parameters: z.object({
    query: z.string().describe("搜索关键词"),
  }),
  execute: async ({ query }) => {
    const results = await vectorDB.search(query);
    return results.map(r => r.content).join("\n");
  },
};

const calculateTool = {
  description: "执行数学计算",
  parameters: z.object({
    expression: z.string().describe("数学表达式"),
  }),
  execute: async ({ expression }) => {
    return eval(expression); // 生产环境应使用安全的表达式解析器
  },
};

// 创建 Agent（自动循环调用工具直到完成任务）
const result = await agent({
  model: openai("gpt-4o"),
  tools: { search: searchTool, calculate: calculateTool },
  maxSteps: 10,  // 最多执行 10 轮工具调用
  system: "你是一个研究助手，先搜索相关资料，再基于事实回答问题。",
  prompt: "2026 年全球 AI 市场规模是多少？同比增长率？",
  // Agent 会自动循环：
  // Step 1: 调用 search("2026 AI 市场规模")
  // Step 2: 调用 search("2025 AI 市场规模") （计算增长率）
  // Step 3: 调用 calculate("...") （计算同比增长率）
  // Step 4: 生成最终回答
});

console.log(result.text);         // 最终回答
console.log(result.steps);        // 每一步的工具调用和结果
console.log(result.usage);        // Token 使用统计
```

### 8.4 useAgent Hook：React 中的 Agent 交互

`useAgent` hook 是 `useChat` 的 Agent 增强版——支持多步工具调用、状态观察、流式渲染：

```tsx
import { useAgent } from "@ai-sdk/react";

function ResearchAssistant() {
  const {
    messages,          // 消息历史
    input,             // 当前输入框值
    handleInputChange, // 输入框变化处理
    handleSubmit,      // 提交处理
    isLoading,         // 是否正在加载
    activeStep,        // 当前 Agent 执行步骤
    steps,             // 所有已完成的步骤
  } = useAgent({
    api: "/api/agent",
    maxSteps: 10,
  });

  return (
    <div className="flex flex-col h-screen">
      {/* 消息列表 */}
      <div className="flex-1 overflow-y-auto p-4">
        {messages.map((msg) => (
          <div key={msg.id} className={msg.role === "user" ? "text-right" : ""}>
            {/* 渲染文本部分 */}
            {msg.parts?.filter(p => p.type === "text").map((part, i) => (
              <p key={i}>{part.text}</p>
            ))}
            {/* 渲染工具调用部分 */}
            {msg.parts?.filter(p => p.type === "tool-invocation").map((part, i) => (
              <ToolCallCard
                key={i}
                toolName={part.toolInvocation.toolName}
                args={part.toolInvocation.args}
                result={part.toolInvocation.result}
                state={part.toolInvocation.state}
              />
            ))}
          </div>
        ))}
      </div>

      {/* Agent 执行进度 */}
      {activeStep && (
        <div className="bg-blue-50 p-2 text-sm">
          🔄 Agent 正在执行第 {steps.length + 1} 步...
        </div>
      )}

      {/* 输入区域 */}
      <form onSubmit={handleSubmit} className="p-4 border-t">
        <input value={input} onChange={handleInputChange} />
        <button type="submit" disabled={isLoading}>发送</button>
      </form>
    </div>
  );
}
```

### 8.5 Generative UI：从文本到交互式组件

Generative UI 是 2026 年 AI 前端最重要的范式转变之一——Agent 不只输出文本，还能**动态生成 UI 组件**。

生活化类比：传统 ChatBot 像纯文字短信，Generative UI 像微信小程序——聊天中直接嵌入可交互的卡片、表单、图表。

```tsx

// 定义工具对应的 UI 组件
function WeatherCard({ city, temperature, condition }) {
  return (
    <div className="rounded-lg bg-gradient-to-r from-blue-400 to-blue-600 p-4 text-white">
      <h3 className="text-lg font-bold">{city}</h3>
      <p className="text-3xl">{temperature}°C</p>
      <p>{condition}</p>
    </div>
  );
}

function StockChart({ symbol, data }) {
  return <LineChart data={data} title={`${symbol} 股价走势`} />;
}

// 根据工具调用状态渲染不同 UI
function ToolCallCard({ toolName, args, result, state }) {
  // state: "partial-call" → "call" → "result"
  // 对应 Vercel AI SDK 的 UIToolInvocation 生命周期

  if (state === "partial-call") {
    // 工具参数还在流式传输中
    return <Skeleton className="h-24 w-full" />;
  }

  if (state === "call") {
    // 工具已被调用，等待结果
    return <LoadingCard toolName={toolName} />;
  }

  // state === "result"，渲染工具结果的 UI 组件
  switch (toolName) {
    case "getWeather":
      return <WeatherCard {...result} />;
    case "getStockPrice":
      return <StockChart {...result} />;
    case "searchProducts":
      return <ProductGrid products={result.items} />;
    default:
      return <pre>{JSON.stringify(result, null, 2)}</pre>;
  }
}
```

### 9.4 Chat UI 与共享状态

```tsx
import {
  CopilotKit,
  CopilotSidebar,
  useCopilotReadable,
  useCopilotAction,
} from "@copilotkit/react";

function App() {
  return (
    // CopilotKit 上下文提供者
    <CopilotKit runtimeUrl="/api/copilotkit">
      <MainContent />
      {/* 开箱即用的侧边栏聊天 UI */}
      <CopilotSidebar
        labels={{ title: "AI 助手", placeholder: "问我任何问题..." }}
      />
    </CopilotKit>
  );
}

function MainContent() {
  const [todos, setTodos] = useState([
    { id: 1, text: "学习 AG-UI", done: false },
    { id: 2, text: "搭建 CopilotKit 项目", done: false },
  ]);

  // 1. 共享状态：让 Agent 能"看到"当前的待办事项
  useCopilotReadable({
    description: "用户当前的待办事项列表",
    value: todos,
  });

  // 2. 前端工具：让 Agent 能"操作"待办事项
  useCopilotAction({
    name: "addTodo",
    description: "添加一个新的待办事项",
    parameters: [
      { name: "text", type: "string", description: "待办事项内容" },
    ],
    handler: async ({ text }) => {
      setTodos(prev => [...prev, { id: Date.now(), text, done: false }]);
      return `已添加待办：${text}`;
    },
  });

  useCopilotAction({
    name: "completeTodo",
    description: "标记一个待办事项为完成",
    parameters: [
      { name: "id", type: "number", description: "待办事项 ID" },
    ],
    handler: async ({ id }) => {
      setTodos(prev =>
        prev.map(t => t.id === id ? { ...t, done: true } : t)
      );
      return `已完成待办 #${id}`;
    },
  });

  return (
    <ul>
      {todos.map(t => (
        <li key={t.id} style={{ textDecoration: t.done ? "line-through" : "" }}>
          {t.text}
        </li>
      ))}
    </ul>
  );
}
```

### 9.5 Generative UI 三种模式

CopilotKit 支持三种 Generative UI 模式，从简单到灵活递进：

#### 模式 1：Static（AG-UI Protocol）

预定义组件映射到工具调用——最可靠、最可控：

```tsx
import { useCopilotAction } from "@copilotkit/react";

// 工具调用时渲染预定义的 React 组件
useCopilotAction({
  name: "showWeather",
  description: "显示天气信息",
  parameters: [
    { name: "city", type: "string" },
  ],
  // render 函数：根据工具调用状态渲染 UI
  render: ({ args, status, result }) => {
    if (status === "executing") {
      return <WeatherSkeleton city={args.city} />;
    }
    return <WeatherCard {...result} />;
  },
  handler: async ({ city }) => {
    const weather = await fetchWeather(city);
    return weather;
  },
});
```

#### 模式 2：Declarative（A2UI）

Agent 指定组件类型和 props——后端控制渲染：

```typescript

})
```

## 10. 企业级 AI 组件库

### 10.1 为什么需要专用 AI 组件库？

想象你要开一家咖啡店。你可以从零开始——自己设计杯子、自己做吧台、自己搭收银系统。但更聪明的做法是购买专业的咖啡器具套装——标准化、专业设计、开箱即用。

**AI 组件库就是"AI 应用的专业器具套装"——专为 AI 交互场景设计的 UI 组件集合，解决了聊天气泡、流式渲染、附件上传、思维链展示等共性问题。**

### 10.2 Ant Design X（@ant-design/x）

Ant Design X 是蚂蚁集团 Ant Design 团队推出的企业级 AI 组件库，遵循 **RICH 交互范式**：

```
RICH 交互范式：
┌──────────────────────────────────────────┐
│  R - Request（请求）                      │
│  └── 用户发起意图（文本/语音/文件上传）    │
│                                          │
│  I - Interpret（解读）                    │
│  └── AI 理解意图，展示思考过程             │
│                                          │
│  C - Convert（转化）                      │
│  └── AI 生成结果，转化为可交互的 UI        │
│                                          │
│  H - Help（帮助）                         │
│  └── 引导用户下一步操作（建议/快捷操作）   │
└──────────────────────────────────────────┘
```

```tsx
            content={msg.content}

            typing={msg.isStreaming}  // 流式输出时显示打字动画
            avatar={msg.role === "assistant" ? { icon: "🤖" } : undefined}
          />
        ))}
      </div>

      {/* 建议面板 */}
      <Suggestion
        items={["继续分析", "换个角度", "生成图表"]}
        onSelect={(item) => handleSend(item)}
      />

      {/* 输入框 */}
      <Sender
        placeholder="输入你的问题..."
        onSubmit={handleSend}
        allowSpeech           // 语音输入
        actions={[
          { key: "attachment", icon: "📎", onClick: handleAttachment },
        ]}
      />
    </div>
  );
}
```

#### BYOF（Bring Your Own Function）

```python
# Open WebUI 的 Python 原生函数扩展
# 用户可以用纯 Python 编写自定义工具函数

class Tools:
    """自定义工具类 — 注册后 Agent 可直接调用"""

    def calculate_compound_interest(
        self,
        principal: float,
        rate: float,
        years: int
    ) -> str:
        """
        计算复利收益。
        :param principal: 本金
        :param rate: 年利率（如 0.05 表示 5%）
        :param years: 投资年数
        :return: 最终金额和收益
        """
        amount = principal * (1 + rate) ** years
        profit = amount - principal
        return f"本金: {principal}, {years}年后: {amount:.2f}, 收益: {profit:.2f}"

    def query_database(self, sql: str) -> str:
        """
        查询内部数据库。
        :param sql: SQL 查询语句
        :return: 查询结果
        """
        # 直接使用 Python 连接数据库，无需额外 API 层
        import sqlite3
        conn = sqlite3.connect("business.db")
        result = conn.execute(sql).fetchall()
        conn.close()
        return str(result)
```

## 12. 常见陷阱与最佳实践

> 以下总结了 AI 前端开发中最常见的反模式和对应的最佳实践：

### ❌ 陷阱 1：自建流式协议

```
❌ 每个项目自定义流式协议格式

// 项目 A：
data: {"type": "chunk", "text": "你好"}
// 项目 B：
event: message\ndata: {"delta": "你好"}
// 项目 C：
{"stream": true, "content": "你好"}\n

→ 换一个 Agent 框架就要重写整个前端流式处理
```

```
✅ 使用 AG-UI 标准协议

// 所有 Agent 框架使用统一事件格式
event: TEXT_MESSAGE_CONTENT
data: {"delta": "你好", "messageId": "msg-001"}

→ 前端一套代码对接 LangGraph、CrewAI、PydanticAI 等所有框架
```

### ❌ 陷阱 2：忽略 Generative UI，只做纯文本

```
❌ 所有 AI 响应都渲染为纯文本

// Agent 返回天气数据，但只显示为文本
"北京今天晴，25°C，湿度 45%，东北风 3 级"

→ 用户体验差，信息密度低，无法交互
```

```
✅ 根据工具调用动态渲染 UI 组件

// 同样的天气数据，渲染为交互式天气卡片
<WeatherCard
  city="北京"
  temperature={25}
  humidity={45}
  icon="☀️"
  onClick={() => showForecast("beijing")}
/>

→ 信息展示更直观，用户可以点击查看更多
```

### ❌ 陷阱 3：Agent 状态前后端不同步

```
❌ Agent 修改了数据，前端不知道

// Agent 在后端添加了一个待办事项
// 但前端 state 还是旧的，需要用户手动刷新

→ 用户困惑："AI 说添加了，但我看不到"
```

```
✅ 使用 CopilotKit Shared State 或 AG-UI 状态同步

// Agent 通过 STATE_DELTA 事件同步状态到前端
event: STATE_DELTA
data: {"delta": [{"op": "add", "path": "/todos/-", "value": {"text": "新待办"}}]}

// 或使用 CopilotKit 的 useCopilotReadable 双向同步
useCopilotReadable({ description: "待办列表", value: todos });

→ Agent 修改 = 前端实时更新，零延迟同步
```

### ❌ 陷阱 4：手动管理 AI 组件样式

```
❌ 从零手写聊天气泡、流式渲染、思维链展示

// 自己实现打字动画、Markdown 渲染、代码高亮、附件上传...
// 结果：3 个月开发时间，仍有大量边界 case 未处理

→ 重复造轮子，质量不如专业组件库
```

```
✅ 使用 Ant Design X 等成熟组件库

import { Bubble, Sender, ThoughtChain } from "@ant-design/x";

// 开箱即用：流式渲染、打字动画、思维链、附件管理
// 企业级质量：无障碍访问、主题定制、国际化

→ 1 周完成 AI 界面开发，聚焦业务逻辑
```

### ❌ 陷阱 5：所有 AI 交互都走 Chat 形式

```
❌ 任何 AI 功能都做成聊天对话

// 用户想修改一个图表颜色，也要打字告诉 AI
// 用户想批量处理数据，也要在聊天框里一条条输入

→ 简单操作反而变复杂了
```

```
✅ 根据场景选择合适的交互模式

三种 AI 交互模式：

1. Chat（对话式）
   └── 适合：开放式问答、创意生成、复杂推理
       例：聊天机器人、写作助手

2. Copilot（嵌入式辅助）
   └── 适合：在现有工作流中提供 AI 建议
       例：代码补全、文档校对、邮件建议

3. Agent Workspace（自主工作区）
   └── 适合：多步骤复杂任务、自主执行
       例：数据分析、报告生成、自动化工作流

→ 匹配场景选模式，而非一切皆 Chat
```

## 总结

AI 应用前端的核心挑战在于将高延迟、逐 Token 生成的 LLM 输出转化为流畅、响应式的用户体验。关键设计决策：

1. **Fetch Streaming 优先 EventSource**：支持 POST Body，更灵活；断连处理更可控
2. **rAF 批量更新**：避免每个 Token 触发 setState，将重渲染频率降至 60fps
3. **Suspense + 流式 RSC**：Next.js App Router 让服务端流式渲染开箱即用
4. **Zustand + immer**：不可变更新简化复杂消息状态管理，persist 中间件零成本持久化
5. **Web Worker 解析**：CPU 密集型 Markdown 解析移出主线程，保证 UI 流畅
6. **动态 import**：highlight.js / KaTeX / Mermaid 按需加载，首屏 JS 减少 60%+
7. **AG-UI 标准协议**：统一 Agent-UI 交互协议，一套前端对接所有 Agent 框架
8. **Generative UI**：从纯文本输出到动态 UI 组件渲染，信息密度和交互性指数级提升
9. **CopilotKit**：Agent-Native 应用的完整解决方案，共享状态 + HITL + 三种 Generative UI 模式
10. **企业级组件库**：Ant Design X 等专用 AI 组件库，开箱即用的聊天气泡、思维链、流式 Markdown
11. **真实项目参考**：LobeChat（React/Next.js）和 Open WebUI（SvelteKit/FastAPI）提供工业级架构范本

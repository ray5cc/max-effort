## 1. 为什么需要高可用与容灾

- **SLA 与收入挂钩**：每 0.1% 的不可用都可能是百万级收入损失。
- **法规与信任**：金融、医疗需满足恢复时间/点目标（RTO/RPO）。
- **复杂性上升**：云原生/多区域/多依赖链路让故障呈现“多米诺”。

> 生活类比：城市供水有多个水厂与水管环路，一条管道破裂仍能供水；高可用系统也是要有备用“水厂”和“分流阀门”。

## 2. 核心概念（是什么）

- **可用性指标**：SLA（对外承诺）、SLO（内部目标）、SLI（可观测度量）。
- **RTO/RPO**：恢复时间目标 / 恢复点目标，决定备份与复制策略。
- **HA vs DR vs BC**：
  - HA（高可用）：单区域内避免单点，快速自动故障切换。
  - DR（灾备）：跨区域/跨机房，面对极端故障的恢复能力。
  - BC（业务连续性）：包含组织流程、演练、通信与人员。
- **故障域**：实例/可用区/区域/供应商；设计要跨故障域隔离。
- **一致性与分区容忍**：CAP 下跨地域多活需在一致性与可用性间取舍。

## 3. 架构与数据路径设计（怎么做）

### 3.1 拓扑模式

| 模式 | 描述 | 适用场景 | 代价 |
| ---- | ---- | -------- | ---- |
| 单活 + 冷备 | 主站服务，备站仅同步数据，手动切换 | 成本敏感、低频恢复 | RTO 较长 |
| 双活 / 多活 | 多区域同时接流量，写入需冲突解决或分区路由 | 全球/跨区低延迟 | 数据一致性与流量调度复杂 |
| 主备热切 | 备站实时同步，健康检查自动切换 | 对停机敏感但可接受短暂中断 | 网络/复制带宽成本 |

### 3.2 数据复制与一致性

- **同步复制**：强一致，延迟高，跨区域成本大；适合账务、订单。
- **异步复制**：低延迟，存在数据丢失风险；适合非关键日志。
- **半同步 / Quorum**：多数派提交后返回，兼顾数据安全与延迟。
- **冲突解决**：分区路由（按用户/租户哈希）、CRDT、版本向量。

### 3.3 流量调度与健康检查

- **入口层**：Anycast + GeoDNS + 全球流量管理（GTM），按地理/健康/负载分配。
- **服务层**：Sidecar/Service Mesh 健康探针（L7），熔断、重试、超时。
- **数据层**：读写分离、故障转移（Promote Replica）、自动主从重选（Raft/Paxos）。

### 3.4 保护与降级

- **熔断与限流**：防止雪崩效应，优先保障核心路径。
- **隔离**：线程池/连接池隔离；舱壁模式隔离租户或业务域。
- **降级策略**：关闭非关键特性、延迟队列、缓存兜底、只读模式。

### 3.5 恢复与演练

- **Runbook**：切换步骤、回退条件、预期指标影响。
- **演练**：Chaos/故障注入、流量回放；验证 RTO/RPO 与值班熟练度。
- **数据校验**：校对主备一致性（行数/校验和）、对账。

## 4. 实践案例：多活电商订单通道

**目标**：订单成功率 ≥ 99.95%，RPO ≤ 30 秒，RTO ≤ 5 分钟。

1. **分区路由**：按用户 ID 取模到区域 A/B，写入保持“同用户同分区”，降低跨区写冲突。
2. **数据层**：主写区域内使用多副本 Raft；跨区域异步复制 + 关键表半同步（仅订单表）。
3. **入口流量**：GTM 根据健康/延迟调度，区域故障时 30 秒内切流。
4. **缓存与队列**：下单链路前置库存缓存，使用消息队列异步触发后置履约，保证峰值削峰。
5. **恢复演练**：每月演练“单区域完全故障”与“数据库主库不可用”，对照 RTO/RPO。

ASCII 示意：

```
Client
  │
  ├─▶ GeoDNS/GTM ──▶ Region A (写主) ──▶ Raft DB (同步复制)
  │                 │                       │
  │                 └─▶ MQ / Cache          └─▶ Async Replicate ──▶ Region B (候选主)
  │
  └─▶ Region B (分区写或切流后主) ──▶ Raft DB (半同步关键表)
```

## 5. 常见陷阱与最佳实践

- **陷阱：复制延迟导致回退**——异步复制时切主可能造成回退/数据丢失；关键表用半同步或双写比对。
- **陷阱：健康检查误判**——短暂抖动触发错误切换；需多探针、分级阈值、冷却时间。
- **陷阱：跨区一致性开销过高**——强一致跨洋写延迟爆炸；采用分区路由或多写 CRDT + 业务补偿。
- **最佳实践**：
  - 以 SLO/RTO/RPO 反推架构与成本，量化而非“拍脑袋”。
  - 同步 + 异步混合：关键数据强保护，非关键数据异步降成本。
  - “演练优先于文档”：定期故障演练 + Runbook 走查，确保切换可重复。
  - 度量闭环：切换时间、数据丢失量、Error Budget 消耗率纳入可观测性。

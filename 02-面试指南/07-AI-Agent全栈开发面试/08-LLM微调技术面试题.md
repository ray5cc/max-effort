## 基础题（适合初级，0~1年经验）

### Q1：什么是微调（Fine-Tuning）？为什么不直接使用预训练模型？

**参考答案：**
微调是在预训练模型的基础上，使用特定任务或领域的数据对模型参数进行进一步训练的过程。

不能直接使用预训练模型的主要原因：
1. **行为对齐**：预训练模型只会"续写"文本，不擅长回答问题；需要 Instruction Tuning 让模型学会"指令跟随"
2. **领域适配**：通用模型在医疗、法律等垂直领域专业词汇和推理方式上能力有限
3. **格式规范**：需要稳定输出 JSON、Markdown 等结构化格式
4. **安全对齐**：预训练模型可能生成有害内容，需要 RLHF/DPO 进行价值观对齐

**扩展知识：** 微调并不是唯一选择，RAG（检索增强生成）和 Prompt Engineering 在许多场景下是更经济的替代方案。选择微调的场景通常是：数据格式高度特殊、任务需要大量领域知识、Prompt 无法稳定控制输出。

---

### Q2：什么是 LoRA？它的核心思想是什么？

**参考答案：**
LoRA（Low-Rank Adaptation）是一种参数高效微调方法。

**核心思想：** 大型预训练模型的参数更新矩阵 ΔW 具有**低内在秩**（low intrinsic rank）特性——即使权重维度很高，有效的更新信息维度也很低。

**实现方式：**
- 冻结原始权重矩阵 W₀
- 在旁路插入低秩分解：ΔW = B × A，其中 B ∈ R^(d×r)，A ∈ R^(r×k)，r << min(d,k)
- 前向传播：`h = W₀x + α/r × BAx`（α 为缩放系数）
- 训练结束后可将 BA 合并回 W₀，**推理零开销**

**参数量对比：**
- 原始矩阵参数：d × k
- LoRA 参数：r × (d + k)，当 r=8, d=k=4096 时约减少 99.6%

**扩展知识：** LoRA 默认应用于注意力层的 Q、V 矩阵，也可扩展到 K、O 矩阵和 FFN 层（`target_modules="all-linear"`）。

---

### Q3：LoRA 和 QLoRA 的区别是什么？

**参考答案：**
QLoRA = 4-bit 量化基础模型 + LoRA 适配器。

| 特性 | LoRA | QLoRA |
|------|------|-------|
| 基础模型精度 | FP16/BF16 | 4-bit NF4 量化 |
| 适配器精度 | FP16/BF16 | FP16/BF16 |
| 显存需求 | 中等 | 极低 |
| 质量损失 | 无 | 轻微（通常 < 1%） |
| 代表使用场景 | 24GB+ GPU 微调 7B~13B | 24GB GPU 微调 65B+|

QLoRA 的三项关键技术：
1. **NF4 量化**：专为正态分布权重设计的 4-bit 量化格式
2. **双重量化**：对量化常数再量化，多节省约 0.37 bits/参数
3. **分页优化器**：将优化器状态分页至 CPU，防止 OOM

**扩展知识：** QLoRA 由华盛顿大学 Tim Dettmers 等人于 2023 年提出，论文《QLoRA: Efficient Finetuning of Quantized LLMs》证明了 4-bit 量化几乎不影响微调效果。

### Q4：什么是 RLHF？请描述其三个阶段。

**参考答案：**
RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）是让语言模型与人类偏好对齐的训练方法，ChatGPT 和 InstructGPT 都使用了这种方法。

**三个阶段：**

1. **监督微调（SFT, Supervised Fine-Tuning）**
   - 收集高质量的"问题-答案"对（人工标注）
   - 使用这些数据对预训练模型进行全量或 LoRA 微调
   - 目标：让模型学会"如何回答问题"（指令跟随）

2. **奖励模型训练（RM, Reward Model）**
   - 收集"比较数据"：同一问题的多个回答，由标注者排序
   - 训练一个奖励模型，使其能预测"哪个回答更好"
   - 奖励模型通常与 SFT 模型架构相同，但最后一层改为输出分数

3. **PPO 强化学习（Policy Optimization）**
   - 用 SFT 模型初始化策略模型
   - 策略模型生成回答 → 奖励模型打分 → PPO 更新策略模型
   - 加入 KL 散度惩罚，防止策略模型偏离 SFT 模型太远

**扩展知识：** RLHF 的主要挑战：(1) 人工标注成本高；(2) 奖励黑客（模型找到高分但不好的回答方式）；(3) PPO 训练不稳定。这催生了 DPO 等更简单的替代方案。

---

### Q5：Adapter Tuning 的原理是什么？与 LoRA 有何区别？

**参考答案：**
Adapter Tuning 在 Transformer 每层的 FFN 之后插入小型适配器模块，结构为：

```
输入 → LayerNorm → 线性层（d→m，m<<d）→ 激活（GELU）→ 线性层（m→d）→ + 残差 → 输出
```

**与 LoRA 的区别：**

| 特性 | LoRA | Adapter |
|------|------|---------|
| 插入位置 | 权重旁路（并联） | FFN 后（串联） |
| 推理开销 | 无（可合并权重） | 有（串行计算增加延迟） |
| 多任务支持 | 需要合并，不便切换 | 可热插拔不同 Adapter |
| 参数量 | 更少（< 1%）| 略多（1~3%） |

**Adapter 适合的场景：** 需要为同一基础模型提供多个不同任务的服务时，可以加载一个基础模型 + 多个 Adapter，按需切换，节省内存。

## 进阶题（适合中级，1~3年经验）

### Q6：DPO 如何绕过奖励模型？推导其损失函数。

**参考答案：**
DPO（Direct Preference Optimization）利用了 RLHF 目标和奖励模型之间的数学等价关系。

**推导过程：**

RLHF 的目标是最大化：
```
E[r(x,y)] - β × KL(π || π_ref)
```

这个优化问题有闭合形式的最优解：
```
π*(y|x) = π_ref(y|x) / Z(x) × exp(r(x,y) / β)
```

其中 Z(x) 是归一化常数。

反解出奖励函数：
```
r(x,y) = β × log(π*(y|x) / π_ref(y|x)) + β × log Z(x)
```

代入 Bradley-Terry 偏好模型 `P(y_w > y_l) = σ(r(y_w) - r(y_l))`：

```
P(y_w > y_l | x) = σ(β × [log π(y_w|x)/π_ref(y_w|x) - log π(y_l|x)/π_ref(y_l|x)])
```

注意 `log Z(x)` 项在相减时消掉了！因此 DPO 的损失函数为：

```
L_DPO = -E[log σ(β × (log π(y_w|x)/π_ref(y_w|x) - log π(y_l|x)/π_ref(y_l|x)))]
```

**关键洞察：** 模型参数化了奖励函数，省去了单独训练奖励模型的步骤。

**扩展知识：** DPO 的局限性：(1) 不支持在线（online）偏好学习，只能离线训练；(2) 对参考模型质量敏感；(3) 在数学/代码等有明确验证标准的任务上不如 GRPO。

---

### Q7：GRPO 与 PPO 的核心区别是什么？

**参考答案：**
GRPO（Group Relative Policy Optimization）由 DeepSeek 提出，是 PPO 的简化版。

**核心区别：**

| 维度 | PPO | GRPO |
|------|-----|------|
| 优势估计 | 需要 Critic（价值模型） | 使用组内相对奖励估计 |
| 模型数量 | 4个（策略、参考、奖励、价值）| 2个（策略+采样）|
| 显存需求 | 极高 | 较低 |
| 奖励来源 | 奖励模型打分 | 可用规则验证（代码/数学）|

**GRPO 的优势估计：**
```
对同一问题 x，采样 G 个回答 {y₁,...,yG}
每个回答的优势 = reward(yᵢ) - mean(reward(y₁,...,yG))
```

这消除了 Critic 网络，让训练更稳定，适合有验证器的任务（数学题可以检验答案对错，代码可以运行测试）。

**扩展知识：** DeepSeek-R1 使用 GRPO 进行推理能力训练，采用"过程奖励 + 结果奖励"的混合策略，在数学和代码任务上取得了与 OpenAI o1 相近的性能。

### Q8：如何选择 LoRA 的 `r` 值和 `target_modules`？

**参考答案：**

**选择 `r` 值的原则：**
- `r` 越大：表达能力越强，但参数越多，过拟合风险越高
- 经验规则：数据量 × 1000 < r × 参数量 时开始过拟合
- 推荐：
  - 数据 < 10K 条：r = 8~16
  - 数据 10K~100K 条：r = 32~64
  - 数据 > 100K 条：r = 64~128 或考虑全量微调

**选择 `target_modules`：**
- 最小配置：`["q_proj", "v_proj"]`（只改 Q、V，效果基本达到全量的 90%+）
- 标准配置：`["q_proj", "k_proj", "v_proj", "o_proj"]`（完整注意力层）
- 完整配置：`"all-linear"`（含 FFN，效果最好但参数最多）
- 特殊需求：代码生成任务中 FFN 层比注意力层更重要，建议包含

**调参技巧：** `lora_alpha` 建议设为 `2r`（如 r=16，alpha=32），这样缩放系数 `alpha/r = 2` 保持稳定。

**扩展知识：** LoRA+ 研究发现，对 A 矩阵和 B 矩阵使用不同学习率（B 使用更高学习率）可以提升效果。

### Q9：什么是灾难性遗忘？如何防止？

**参考答案：**
**灾难性遗忘（Catastrophic Forgetting）**：模型在特定任务上微调后，在原有任务上的能力大幅下降。

**发生原因：** 全量微调时，为了适应新数据，模型参数被大幅修改，覆盖了预训练阶段学到的通用知识。

**防止策略：**

1. **使用 LoRA/Adapter**（最有效）：冻结主干，只训练少量旁路参数，原有能力几乎不受影响

2. **数据混合**：在领域数据中混入 10%~20% 的通用数据（如 OpenHermes、Alpaca），保持通用能力

3. **低学习率**：微调学习率比预训练低 10~100 倍（1e-5 vs 1e-3）

4. **早停（Early Stopping）**：监控通用基准（MMLU、HellaSwag）的分数，一旦下降就停止训练

5. **弹性权重整合（EWC）**：在损失函数中加入正则项，惩罚对"重要参数"的过大修改（学术方法，工程少用）

**扩展知识：** PEFT 方法（LoRA、Adapter）在工程实践中几乎完全解决了灾难性遗忘问题，这是它们流行的主要原因之一。

### Q10：verl 框架解决了什么问题？其架构设计有哪些创新点？

**参考答案：**
verl（字节跳动开源）解决了大规模 LLM 后训练（Post-Training）中的工程挑战：

**问题：**
- 大型模型（70B+）的 RL 训练需要同时维护策略模型（推理）和训练梯度（训练）
- 推理和训练对硬件的要求不同（推理偏向高吞吐，训练偏向高内存带宽）
- 标准 DDP 框架难以高效协调推理+训练的混合工作负载

**架构创新：**

1. **混合控制器（Hybrid Controller）**：Driver（单节点）负责 RL 算法逻辑，Actor Worker（N个节点）负责生成，Critic Worker（M个节点）负责评估，三者可独立扩展

2. **后端解耦**：推理使用 vLLM（优化吞吐量），训练使用 Megatron-LM（优化梯度效率），两者通过 NCCL 通信

3. **内存复用**：推理权重和训练权重共享，减少 GPU-GPU 内存传输

4. **异步执行**：Actor 生成样本的同时，Critic 可评估上一批，提升 GPU 利用率

## 高级题（适合高级，3年以上经验）

### Q11：KL 散度惩罚在 RLHF 中的作用是什么？如果 β 设置过大或过小会发生什么？

**参考答案：**
**KL 散度惩罚的作用：**
```
总奖励 = reward_score - β × KL(π_current || π_ref)
```

防止**奖励黑客（Reward Hacking）**：策略模型可能学到一些能"欺骗"奖励模型但实际质量差的输出模式（如极长回答、特定重复词语），KL 惩罚约束策略模型不能偏离参考模型太远。

**β 过大：**
- KL 惩罚主导，策略更新非常保守
- 模型几乎不变，无法有效对齐
- 表现为：训练损失收敛，但效果几乎等于 SFT 基线

**β 过小（接近 0）：**
- 几乎无约束，策略模型可自由优化奖励
- 容易发生奖励黑客：模型输出变得怪异（过长、重复、乱码）
- 表现为：奖励分数很高，但人类评估很差

**推荐值：** β 通常在 0.01~0.1 之间；DPO 中 β = 0.1 是常见默认值；PPO 中通常使用自适应 KL 控制（目标 KL 约为 0.01~0.02）。

### Q12：Prefix Tuning 和 P-Tuning v2 的区别？各适合哪类任务？

**参考答案：**

**Prefix Tuning（2021）：**
- 在输入序列前添加可学习的 k 个"虚拟 Token"（Prefix）
- Prefix 参数通过 MLP 生成（直接优化 Prefix 参数不稳定）
- 只在输入层插入，深层 Transformer 层不感知 Prefix
- 参数量约 0.1% 以下

**P-Tuning v2（2022）：**
- 改进：在**所有层**都插入可学习 Prefix（深度提示）
- 效果大幅提升，在某些任务上媲美全量微调
- 不需要 MLP 生成，直接优化更稳定

**任务适配：**

| 方法 | 适合任务 | 不适合任务 |
|------|---------|---------|
| Prefix Tuning | 摘要、翻译（生成任务） | 分类任务（效果差）|
| P-Tuning v2 | NLU 任务（分类、理解）、NLG 任务 | 参数极其受限的场景 |
| LoRA | 几乎所有任务 | 无明显不适合场景 |

**扩展知识：** P-Tuning（v1）通过 LSTM 生成 Prompt，而 P-Tuning v2 改为直接在每层插入可训练参数，更接近 Prefix Tuning 的思想，但应用范围更广。

### Q13：如何评估微调后的模型质量？有哪些常用基准？

**参考答案：**

**自动评估基准：**

| 基准 | 评估内容 | 说明 |
|------|---------|------|
| MMLU | 多学科知识（57个科目）| 衡量知识广度 |
| HellaSwag | 常识推理（句子补全）| 衡量语言理解 |
| HumanEval | Python 代码生成（164题）| 代码能力 |
| GSM8K | 小学数学应用题（8500题）| 数学推理 |
| MT-Bench | 多轮对话质量 | GPT-4 评分 |
| AlpacaEval | 指令跟随能力 | 与参考模型对比 |

**微调效果评估最佳实践：**
1. 使用 lm-evaluation-harness 统一评估（EleutherAI 开源）
2. 监控领域任务指标（如领域 F1、准确率）
3. 同时监控通用基准，确保未发生灾难性遗忘
4. 使用 MT-Bench/AlpacaEval 评估对话质量（相比 MMLU 更接近真实使用）
5. **人工评估**：对于高风险应用，必须加入人工盲测

### Q14：在显存有限（单卡 24GB）的情况下，如何微调一个 13B 参数的模型？

**参考答案：**

**方案：QLoRA（4-bit 量化 + LoRA）**

显存估算（13B 模型，BF16）：
- 全量微调：13B × 2 bytes × 4（参数+梯度+优化器状态）= 104GB ❌
- LoRA (FP16 基模)：13B × 2 + 优化器 ≈ 52GB ❌
- QLoRA (4-bit 基模)：13B × 0.5 bytes (int4) + LoRA ≈ **8~10GB** ✅

**完整配置：**
```python
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
from peft import prepare_model_for_kbit_training, LoraConfig, get_peft_model

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_use_double_quant=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
)

model = AutoModelForCausalLM.from_pretrained("model_id", quantization_config=bnb_config)
model = prepare_model_for_kbit_training(model)  # 开启梯度检查点

lora_config = LoraConfig(r=64, lora_alpha=16, target_modules="all-linear")
model = get_peft_model(model, lora_config)
```

**其他优化：**
- 开启 `gradient_checkpointing=True`（节省约 60% 显存，训练变慢约 30%）
- 使用 `gradient_accumulation_steps=8` 模拟大 batch（不增加显存）
- 批次大小设为 1，配合梯度累积
- 使用 Flash Attention 2（需要 Ampere+ GPU）

## 场景题（开放性问题）

### Q15：你需要为一家医院构建一个医疗诊断辅助 LLM，数据有 50K 条医生诊断记录（脱敏）。你会选择什么微调方案？如何评估效果？

**参考思路：**

**方案选择：**
1. **基础模型**：选择 LLaMA 3.1-8B（开源、可私有化部署、无数据隐私风险）
2. **微调方案**：QLoRA SFT（50K 数据量适中，使用 r=32）
3. **对齐训练**：考虑 DPO（用资深医生的偏好评级作为偏好数据）

**数据处理：**
- 格式化为 `{"instruction": "...", "input": "患者症状...", "output": "诊断分析..."}` 格式
- 数据清洗：去除低质量记录、格式统一
- 数据集划分：80% 训练，10% 验证，10% 测试

**评估方案：**
- 自动评估：BLEU/ROUGE（与参考诊断的相似度）
- 领域评估：Accuracy on 疾病分类任务、医学考试题（USMLE）
- 专家评估：由医生对随机抽样的输出进行盲测评分（最重要）
- 安全性评估：是否生成危险建议、是否存在虚构

**生产注意事项：**
- 部署于私有服务器（不可使用云端 API）
- 输出必须有不确定性说明（"建议咨询专科医生"）
- 建立持续监控和人工审核机制

### Q16：RLHF 中，如果奖励模型与人类判断产生显著偏差，应如何处理？

**参考思路：**

**问题诊断：**
1. 收集奖励模型预测与人类判断不一致的样本
2. 分析不一致的模式：长度偏差？风格偏好？领域知识？
3. 计算奖励模型准确率（与人类判断的一致性）

**常见问题及解决：**
- **长度偏差**：奖励模型偏好长回答 → 在奖励中减去长度惩罚项
- **风格偏差**：偏好某种写作风格 → 增加风格多样性的训练数据
- **知识盲区**：专业领域判断不准 → 在该领域补充标注数据重新训练

**系统性解决方案：**
1. 使用**奖励模型集成**（多个 RM 投票），降低单个 RM 偏差的影响
2. 引入**宪法 AI（Constitutional AI）** 原则，用规则约束补充 RM
3. 在生产中持续收集人类反馈，定期重训奖励模型（迭代改进）
4. 考虑切换到 DPO（绕过 RM），直接在最新偏好数据上训练

---

### Q17：一个团队完成了 DPO 训练，但发现模型的输出过于保守（拒绝很多合理请求）。如何诊断和修复？

**参考思路：**

**诊断步骤：**
1. 检查 β 值：如果 β 过大（> 0.3），KL 约束太强，模型过于保守
2. 检查偏好数据：是否存在大量"rejected"样本包含正常内容？数据质量问题
3. 查看训练日志：chosen 样本的概率是否在上升，rejected 是否在下降？
4. 测试基准：对比 SFT 基线和 DPO 模型的拒绝率

**修复方案：**
- **降低 β**（如从 0.1 降至 0.05）：减弱 KL 约束，允许更大胆的更新
- **清洗数据**：去除标注有问题的偏好对（selected/rejected 差异不明显的样本）
- **增加 SFT 数据**：在 DPO 训练集中混入 10% 的 SFT 数据（保持基本能力）
- **使用 KTO**：如果偏好数据难以配对，KTO 对单样本奖励更鲁棒
- **后处理**：调整系统 Prompt，明确说明助手应该乐于帮助合理请求

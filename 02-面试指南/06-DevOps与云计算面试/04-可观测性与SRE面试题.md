## ⭐ 基础题

1) **SLI、SLO、Error Budget 的区别？如何用在发布策略里？**  
**答：**SLI 是可量化指标（成功率/延迟）；SLO 是目标（如 99.9% 四周滚动）；Error Budget=1-SLO，剩余额度决定发布节奏。预算耗尽 → 冻结发布，优先可靠性工作。

2) **Golden Signals vs RED 有何差异？**  
**答：**Golden Signals（Latency/Traffic/Errors/Saturation）通用，适合请求与基础设施；RED（Rate/Errors/Duration）更聚焦微服务/网关的请求型业务，弱化资源饱和度。

3) **为什么日志必须结构化？**  
**答：**便于检索、聚合、关联 Trace ID；避免正则解析脆弱；支持基于字段的告警与审计。结构化是将日志变成“表”，不是纯文本。

4) **什么是 Toil，如何降低？**  
**答：**重复、可脚本化且无长期价值的运维工作。降低方式：自动化（脚本/Runbook）、自愈（重启/扩容）、平台化（统一流水线）。

5) **什么是 P99，为什么常用？**  
**答：**99% 请求的延迟下界，反映长尾体验；比平均值更贴近真实用户感受。P99 上升通常意味着局部热点或下游慢。

6) **Trace 中的 Span 有哪些关键字段？**  
**答：**trace_id、span_id、parent_id、name、timestamp/duration、attributes（标签）、status（OK/Error）、events（异常/日志），用于重建调用树。

7) **告警和监控的区别？**  
**答：**监控是收集与呈现数据，告警是基于阈值/规则产生动作。监控回答“发生了什么”，告警提醒“需要行动”。

8) **什么是无责 Postmortem？**  
**答：**不指责个人，聚焦系统与流程改进；包含时间线、根因、影响、修复、行动项与负责人/截止时间。

## ⭐⭐ 进阶题

1) **如何设计 Error Budget 驱动的发布节奏？**  
**答：**设定 SLO → 计算预算 → 观测消耗速率。预算健康（>50%）保持正常节奏；快速燃耗时启用灰度/金丝雀；预算耗尽冻结发布并把容量、可靠性工作列为优先级。

2) **高基数标签如何治理？**  
**答：**避免用户 ID/订单号，改用分级或采样；在 OTel Collector/Prometheus relabel 过滤；为异常请求单独采样；定期审计标签基数。

3) **Head Sampling 与 Tail Sampling 选择？**  
**答：**Head 在入口决定采样率，成本低但可能丢异常；Tail 基于后端决策，能保留慢/错请求，适合关键路径，代价是需要缓冲与二次判断，常用两者结合。

4) **多窗口多燃耗（MWMB）告警的原理？**  
**答：**用不同时间窗口计算 Burn Rate：短窗口捕获瞬时爆发，长窗口避免误报。只有当短+长窗口都超阈值才触发，平衡敏感度与稳定性。

5) **如何在微服务中确保 Trace 不丢失？**  
**答：**统一 W3C `traceparent`，网关注入；语言 SDK 自动传播；消息队列透传 Trace ID 到消息头；异步任务开始时重建上下文。

6) **Prometheus 直连 vs 远程存储（Thanos/Cortex/Mimir）？**  
**答：**直连简单但受限单实例存储；远程存储支持长保留、横向扩展、全局查询。代价是复杂度与查询延迟上升，需分层缓存与查询限流。

7) **如何设计高质量的 Dashboard？**  
**答：**主页展示 Golden Signals + SLO；每个面板有阈值与期望解释；支持从指标跳转 Trace/日志；避免炫彩“彩虹图”，突出决策信息。

8) **什么是 Toil 指标？**  
**答：**Toil 百分比 =（重复/机械性工作时间）/（总工作时间），SRE 目标通常 <50%，通过自动化/平台化持续降低。

9) **值班交接要包含哪些信息？**  
**答：**当前告警/静默、已知问题与临时措施、在途变更、重要指标趋势、特殊事件窗口（大促/演练），确保下一班能无缝接力。

## ⭐⭐⭐ 高阶题

1) **如何基于 SLO 设计降级策略？**  
**答：**当 Burn Rate 超阈值时，按 Runbook 依次：限流低优先级流量、关闭次要特性、切只读、降级第三方调用；每步都有“预期影响”与回滚条件。

2) **采样策略对成本和可见性的权衡？**  
**答：**指标低成本高聚合度；Trace 需采样。可以对成功请求低采样，错误/高延迟高采样；按业务价值动态采样；冷数据降分辨率存档。

3) **如何处理跨区域的全链路追踪？**  
**答：**统一 Trace ID 格式，边界层重新父子关联；Region 维度标签；集中或分区汇聚（可用 Tempo/Jaeger 联邦）；注意时钟同步与采样一致性。

4) **告警风暴怎么抑制？**  
**答：**设置抑制规则（下游故障抑制上游连锁告警）、批量聚合、抖动去重、静默窗口（维护/演练）、错误预算触发的全局静默，再用事后复盘优化阈值。

5) **如何将可观测性嵌入开发流程（左移）？**  
**答：**模板化仪表（SDK/库默认指标）、Review 检查 SLI/Logging、在 CI 检查仪表是否暴露、预提交验证 Trace 上下文、预置 Dashboard/告警随服务创建自动生成。

6) **SLO 如何避免“虚假健康”？**  
**答：**按用户视角定义 SLI（成功下单而非 200 响应）；区分客户端/服务端错误；排除机器人流量；用分布式追踪拆分“依赖导致的成功率下降”。

7) **多租户观测栈的隔离与限流？**  
**答：**按租户标签限速/配额；查询网关限流；租户级存储配额与保留策略；RBAC 控制仪表板访问；避免跨租户高基数标签。

8) **当 SLO 与业务 KPI 冲突时如何决策？**  
**答：**展示预算消耗与风险，提供“可控降级”方案；短期可用临时豁免（记录到期时间），长期需要改进架构或重新设定 SLO，使其贴合业务价值。

## 🎯 场景题

1) **场景：大促期间延迟飙升但无错误，如何快速定位？**  
**答：**检查 Golden Signals：延迟升高但错误率正常，多半是饱和。用 Trace 查看等待链（线程池/数据库连接池）；指标看 Saturation、队列长度。临时措施：限流/扩容/开启缓存；事后调整容量模型。

2) **场景：告警风暴导致值班淹没，怎么整改？**  
**答：**梳理告警拓扑，设置父子抑制；合并重复（同主机同错误）；增加静默规则与维护窗口；引入 SLO 驱动告警替代硬阈值；调整路由与分派，确保“少而准”。

3) **场景：跨服务故障定位缓慢，团队抱怨“观测链路断了”**  
**答：**检查 Trace 采样是否丢失；确保网关注入 `traceparent`，消息队列透传；在日志与指标中写入 `trace_id`；为关键链路调高采样/尾采样；在 Dashboard 上支持“指标→Trace→日志”跳转。

## ⭐ 基础题

### Q1：常见排序算法的时间复杂度和稳定性分别是什么？

**参考答案**：

| 算法     | 平均时间   | 最坏时间   | 空间     | 稳定 |
| -------- | ---------- | ---------- | -------- | ---- |
| 冒泡排序 | O(n²)      | O(n²)      | O(1)     | ✅   |
| 选择排序 | O(n²)      | O(n²)      | O(1)     | ❌   |
| 插入排序 | O(n²)      | O(n²)      | O(1)     | ✅   |
| 归并排序 | O(n log n) | O(n log n) | O(n)     | ✅   |
| 快速排序 | O(n log n) | O(n²)      | O(log n) | ❌   |
| 堆排序   | O(n log n) | O(n log n) | O(1)     | ❌   |

**追问**：为什么快速排序不稳定？→ 分区操作中的交换可能改变相等元素的相对位置。

### Q2：什么是排序的"稳定性"？实际工程中什么时候需要稳定排序？

**参考答案**：

稳定性指相等元素排序后保持原来的相对顺序。

**实际场景**：数据库多列排序。先按"部门"排序，再按"工资"排序时，如果第二次排序不稳定，可能打乱同工资员工的部门排列顺序。这就是为什么 Python 的 `sorted()` 和 Java 的 `Arrays.sort(Object[])` 都使用稳定排序（TimSort）。

### Q3：手写二分搜索，并分析为什么 `mid = left + (right - left) // 2` 比 `mid = (left + right) // 2` 更好？

**参考答案**：

```python
def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = left + (right - left) // 2  # 防止 left + right 整数溢出
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1
```

当 `left` 和 `right` 都是非常大的整数时（如 Java 的 `int` 最大值 2³¹-1），`left + right` 会溢出。`left + (right - left) // 2` 在数学上等价但不会溢出。

### Q4：快速排序为什么实践中比归并排序快？

**参考答案**：

虽然两者平均都是 O(n log n)，但快排更快是因为：

1. **缓存友好**：快排在连续内存上原地操作，CPU 缓存命中率高；归并需要额外数组来回复制
2. **常数因子小**：快排的交换操作比归并的元素复制少
3. **分支预测友好**：快排的比较模式对 CPU 分支预测器更友好

但归并排序有自己的优势：**保证 O(n log n)**、**稳定**、**适合链表排序**（不需要随机访问）。

---

### Q5：插入排序在什么场景下比快排更快？

**参考答案**：

1. **数据量很小（n < 50）**：此时 O(n²) 的常数因子小，比 O(n log n) 的递归开销更快
2. **数据近乎有序**：插入排序对几乎有序的数据是 O(n)

这就是为什么 TimSort 在子数组较小时切换到插入排序，快排的优化版本也会在分区小于某个阈值时用插入排序。

### Q6：描述 BFS 和 DFS 的区别，各自适用什么场景？

**参考答案**：

| 特征       | BFS               | DFS          |
| ---------- | ----------------- | ------------ |
| 数据结构   | 队列              | 栈（或递归） |
| 搜索方式   | 层层推进          | 一条路走到底 |
| 空间复杂度 | O(分支因子^深度)  | O(深度)      |
| 最短路径   | ✅ 无权图最短路径 | ❌ 不保证    |

**BFS 适用**：最短路径、层序遍历、社交网络 N 度好友
**DFS 适用**：路径搜索、回溯问题（全排列/子集/N皇后）、拓扑排序、连通分量

### Q7：如何在 O(n) 时间内找到数组中第 K 大的元素？

**参考答案**：

使用**快速选择算法（QuickSelect）**——快排的变体：

```python
import random

def find_kth_largest(nums, k):
    k = len(nums) - k  # 转为第 k 小

    def quickselect(left, right):
        pivot_idx = random.randint(left, right)
        nums[pivot_idx], nums[right] = nums[right], nums[pivot_idx]
        store = left
        for i in range(left, right):
            if nums[i] < nums[right]:
                nums[store], nums[i] = nums[i], nums[store]
                store += 1
        nums[store], nums[right] = nums[right], nums[store]

        if store == k:
            return nums[store]
        elif store < k:
            return quickselect(store + 1, right)
        else:
            return quickselect(left, store - 1)

    return quickselect(0, len(nums) - 1)
```

平均 O(n)，因为每次只需处理一半（n + n/2 + n/4 + ... ≈ 2n）。

### Q8：堆排序的建堆过程为什么是 O(n) 而不是 O(n log n)？

**参考答案**：

虽然单次 heapify 是 O(log n)，但建堆时从底部向上调整，越底层的节点调整距离越短：

- 底层 n/2 个叶节点：不需要调整（0 步）
- 倒数第二层 n/4 个节点：最多调整 1 步
- 倒数第三层 n/8 个节点：最多调整 2 步
- ...
- 根节点 1 个：最多调整 log n 步

总和：n/4 × 1 + n/8 × 2 + n/16 × 3 + ... = O(n)（等比数列求和）

### Q9：在旋转排序数组 [4,5,6,7,0,1,2] 中搜索目标值，要求 O(log n)。

**参考答案**：

关键洞察：旋转数组总有一半是有序的。每次判断 mid 在哪一半，然后确定 target 在有序的那半还是无序的那半。

```python
def search(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = left + (right - left) // 2
        if nums[mid] == target:
            return mid
        if nums[left] <= nums[mid]:  # 左半有序
            if nums[left] <= target < nums[mid]:
                right = mid - 1
            else:
                left = mid + 1
        else:  # 右半有序
            if nums[mid] < target <= nums[right]:
                left = mid + 1
            else:
                right = mid - 1
    return -1
```

### Q10：如何用二分搜索解决"分割数组的最大值最小化"问题？

**参考答案**：

**问题**：将数组分成 m 段，使得各段和的最大值最小。

**关键思路**：二分答案！答案的范围在 [max(nums), sum(nums)] 之间。对于每个候选答案 mid，贪心检查能否分成 ≤ m 段，每段和 ≤ mid。

```python
def split_array(nums, m):
    def can_split(max_sum):
        count, current = 1, 0
        for num in nums:
            if current + num > max_sum:
                count += 1
                current = num
            else:
                current += num
        return count <= m

    left, right = max(nums), sum(nums)
    while left < right:
        mid = left + (right - left) // 2
        if can_split(mid):
            right = mid
        else:
            left = mid + 1
    return left
```

### Q11：归并排序如何统计逆序对数量？

**参考答案**：

在归并合并阶段，当右边元素 < 左边元素时，左边剩余的所有元素都与这个右边元素构成逆序对。

```python
def count_inversions(arr):
    if len(arr) <= 1:
        return arr, 0
    mid = len(arr) // 2
    left, left_inv = count_inversions(arr[:mid])
    right, right_inv = count_inversions(arr[mid:])

    merged, split_inv = [], 0
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i]); i += 1
        else:
            merged.append(right[j]); j += 1
            split_inv += len(left) - i  # 关键：左边剩余元素都是逆序对
    merged.extend(left[i:])
    merged.extend(right[j:])
    return merged, left_inv + right_inv + split_inv
```

### Q12：什么是 TimSort？为什么 Python 和 Java 都采用它？

**参考答案**：

TimSort 是归并排序和插入排序的混合算法：

1. **检测 run**：找到数组中已经有序的连续子序列（自然有序段）
2. **扩展短 run**：用插入排序将短 run 扩展到 minrun 长度（32-64）
3. **归并 run**：用归并排序合并这些 run，维护一个栈保证合并效率

**优势**：

- 对部分有序数据（现实中常见）接近 O(n)
- 最坏情况仍是 O(n log n)
- 稳定排序
- 利用了已有的顺序信息，不做无用功

### Q13：如何在两个有序数组中找到中位数？要求 O(log(min(m,n)))。

**参考答案**：

经典 LeetCode Hard 题。对较短数组做二分，找到一个分割点使得左半部分的所有元素 ≤ 右半部分：

```python
def find_median(nums1, nums2):
    if len(nums1) > len(nums2):
        nums1, nums2 = nums2, nums1
    m, n = len(nums1), len(nums2)
    left, right = 0, m

    while left <= right:
        i = (left + right) // 2  # nums1 的分割点
        j = (m + n + 1) // 2 - i  # nums2 的分割点

        left1 = nums1[i-1] if i > 0 else float('-inf')
        right1 = nums1[i] if i < m else float('inf')
        left2 = nums2[j-1] if j > 0 else float('-inf')
        right2 = nums2[j] if j < n else float('inf')

        if left1 <= right2 and left2 <= right1:
            if (m + n) % 2 == 0:
                return (max(left1, left2) + min(right1, right2)) / 2
            return max(left1, left2)
        elif left1 > right2:
            right = i - 1
        else:
            left = i + 1
```

### Q14：回溯法解决 N 皇后问题的核心思路？

**参考答案**：

逐行放置皇后，检查列、主对角线、副对角线是否冲突。冲突则回溯。

```python
def solve_n_queens(n):
    result = []
    def backtrack(row, cols, diag1, diag2, board):
        if row == n:
            result.append([''.join(r) for r in board])
            return
        for col in range(n):
            if col in cols or (row-col) in diag1 or (row+col) in diag2:
                continue
            board[row][col] = 'Q'
            backtrack(row+1, cols|{col}, diag1|{row-col}, diag2|{row+col}, board)
            board[row][col] = '.'

    backtrack(0, set(), set(), set(), [['.']*n for _ in range(n)])
    return result
```

**关键优化**：用集合（set）O(1) 检查冲突，用 row-col 和 row+col 标识对角线。

### Q15：什么是"二分答案"？举一个例子说明。

**参考答案**：

**思想**：当直接求解困难时，如果答案具有单调性（答案越大/越小，越容易满足条件），就可以二分答案，对每个候选答案用贪心/模拟验证是否可行。

**经典例子**：木材切割——有 N 根木头，要切成 K 段等长的木头，求每段最大长度。

答案范围 [1, max(木头)]，对候选长度 mid，检查每根木头能切 `wood // mid` 段，总段数 ≥ K 则可行。

### Q16：如何对一个链表进行排序？最优时间和空间复杂度是什么？

**参考答案**：

归并排序最适合链表（O(n log n) 时间 + O(1) 空间）：

- 用快慢指针找中点
- 断开链表
- 递归排序两半
- 合并两个有序链表

快排不适合链表（随机访问 pivot 不方便），堆排序也不适合（需要数组随机访问）。

### Q17：解释快速排序的三向切分（3-way partition）及其应用场景。

**参考答案**：

标准快排将数组分为 [< pivot, >= pivot]，三向切分分为 [< pivot, = pivot, > pivot]。当数组有大量重复元素时，标准快排仍是 O(n²)（所有等于 pivot 的元素都在一边），三向切分可以跳过所有等于 pivot 的元素，从 O(n²) 优化到 O(n)。

**应用**：荷兰国旗问题（将 0/1/2 三种元素排序）——一次遍历 O(n) 完成。

### Q18：外部排序的原理是什么？如何优化多路归并？

**参考答案**：

当数据量远大于内存时：

1. **拆分排序**：将数据分成内存大小的块，逐块排序写回磁盘
2. **K 路归并**：打开 K 个有序文件，用**最小堆**维护每个文件当前最小值，每次取堆顶写入输出

**优化**：

- **替代选择**：初始 run 的平均长度可达 2M（M 是内存可容纳的元素数），减少 run 数量
- **I/O 缓冲**：每个文件维护一个输入缓冲区，减少磁盘随机读取
- **败者树**：比最小堆更高效的 K 路归并结构（比较次数更少）

### Q19：如何在无限数据流中维护 Top-K？对比堆和快速选择。

**参考答案**：

| 方法     | 时间       | 空间 | 适用                           |
| -------- | ---------- | ---- | ------------------------------ |
| 最小堆   | O(n log k) | O(k) | **流式数据**（数据持续到来）   |
| 快速选择 | O(n) 平均  | O(n) | **离线数据**（一次性全部可见） |

### Q20：分析 `Arrays.sort()` 在 Java 中对不同类型使用不同算法的原因。

**参考答案**：

- **基本类型（int/double/...）**：使用 **Dual-Pivot QuickSort**（双 pivot 快排），因为基本类型不需要稳定性
- **对象类型（Object[]）**：使用 **TimSort**，因为对象排序需要稳定性（相等对象保持原始顺序可能有业务含义）

双 pivot 快排用两个 pivot 将数组分成三段，减少比较次数，实践中比单 pivot 快排快约 20%。

### Q21：如何实现一个 O(n log n) 的最长递增子序列（LIS）算法？

**参考答案**：

维护一个 **tails 数组**，tails[i] 表示长度为 i+1 的递增子序列的最小末尾元素。对每个新元素，用二分搜索找到它在 tails 中的插入位置。

```python
import bisect

def length_of_lis(nums):
    tails = []
    for num in nums:
        pos = bisect.bisect_left(tails, num)
        if pos == len(tails):
            tails.append(num)  # 扩展最长子序列
        else:
            tails[pos] = num   # 更新为更小的末尾
    return len(tails)
```

**核心洞察**：tails 始终保持有序，所以可以用二分搜索，将朴素 O(n²) DP 优化到 O(n log n)。

### Q22：解释计数排序、基数排序、桶排序三者的关系和各自适用场景。

**参考答案**：

- **计数排序**：直接统计每个值出现次数。适用：值域小的整数（如年龄、分数）。
- **基数排序**：从最低位到最高位，按每一位做稳定排序（通常用计数排序）。适用：定长整数/字符串。
- **桶排序**：将数据分到若干桶中，每个桶内部排序。适用：数据均匀分布在一个范围内。

三者都是**非比较排序**，可以突破 O(n log n) 下界，但都有使用条件（数据类型、范围、分布）。

### Q24：有一个包含 100 亿条 URL 的日志文件（约 1TB），如何找出出现次数最多的 Top-100 URL？

**参考答案**：

1. **哈希分片**：对每条 URL 计算 hash，hash % 1000 分到 1000 个小文件
2. **分别统计**：对每个小文件用 HashMap 统计频率
3. **局部 Top-K**：每个小文件维护大小为 100 的最小堆
4. **全局合并**：1000 个局部结果用 K 路归并得到全局 Top-100

**关键**：相同 URL 一定被分到同一个文件，所以分别统计不会遗漏。

### Q25：你的搜索系统需要对 1000 万条记录的某个字段进行排序返回，但内存只有 2GB，怎么设计？

**参考答案**：

1. **评估数据量**：1000 万条 × 平均 200B/条 ≈ 2GB，刚好放不下
2. **方案 A（数据库下推）**：如果数据在数据库中，利用数据库索引排序（`ORDER BY field LIMIT N`），不要全部加载到内存
3. **方案 B（外部排序）**：分块读取，块内排序，多路归并写出
4. **方案 C（索引优化）**：只将排序字段 + 主键加载到内存（约 200MB），排序后再批量查询完整记录

**追问**：如何支持实时排序？→ 预建排序索引（B+Tree 或跳表），写入时维护有序结构。

### Q26：二分搜索的左边界和右边界模板是什么？如何在旋转排序数组中搜索？如何找峰值元素？⭐⭐⭐

<details>
<summary>参考答案</summary>

**二分搜索的核心难点**：不是"能不能二分"，而是"边界条件怎么写不出 bug"。

**三种模板对比**：

```python
# 模板一：标准二分（找到就返回）
def binary_search(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = lo + (hi - lo) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

# 模板二：左边界（第一个 >= target 的位置，等价于 bisect_left）
def lower_bound(nums, target):
    lo, hi = 0, len(nums)  # 注意：hi = len，不是 len-1
    while lo < hi:          # 注意：< 不是 <=
        mid = lo + (hi - lo) // 2
        if nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid        # 注意：不是 mid-1
    return lo

# 模板三：右边界（最后一个 <= target 的位置）
def upper_bound(nums, target):
    lo, hi = 0, len(nums)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if nums[mid] <= target:
            lo = mid + 1
        else:
            hi = mid
    return lo - 1  # 注意：返回 lo-1
```

**记忆口诀**：
- 左边界 = "第一个满足条件的"，缩右边界 `hi = mid`
- 右边界 = "最后一个满足条件的"，缩左边界 `lo = mid + 1`，返回 `lo - 1`

---

**旋转排序数组搜索（LeetCode 33）**：

```python
def search_rotated(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = lo + (hi - lo) // 2
        if nums[mid] == target:
            return mid

        # 判断哪半边是有序的
        if nums[lo] <= nums[mid]:  # 左半边有序
            if nums[lo] <= target < nums[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        else:                       # 右半边有序
            if nums[mid] < target <= nums[hi]:
                lo = mid + 1
            else:
                hi = mid - 1

    return -1
```

**关键洞察**：旋转数组在任意位置二分后，必有一半是有序的。先判断哪半有序，再判断 target 在不在有序的那半边。

---

**找峰值元素（LeetCode 162）**：

```python
def findPeakElement(nums):
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if nums[mid] < nums[mid + 1]:
            lo = mid + 1   # 峰值在右半边
        else:
            hi = mid        # 峰值在左半边（含 mid）
    return lo
```

**为什么可以二分**：只要 `nums[mid] < nums[mid+1]`，说明右边还在"上坡"，右侧必有峰值。反之左侧必有峰值。这是"二分搜索不一定需要有序数组"的经典例证。

**追问**：如果旋转数组有重复元素（LeetCode 81），最坏情况会退化到什么复杂度？
→ O(n)。当 `nums[lo] == nums[mid] == nums[hi]` 时无法判断哪半有序，只能 `lo++` 或 `hi--` 逐步缩小范围。

### Q27：双指针的常见模式有哪些？用 3Sum、接雨水、滑动窗口最大值三道题说明。⭐⭐⭐

<details>
<summary>参考答案</summary>

**双指针的三种模式**：

| 模式         | 特征                         | 典型题目                        |
| ------------ | ---------------------------- | ------------------------------- |
| 对撞指针     | 左右向中间收拢               | 3Sum、两数之和(有序)、接雨水     |
| 快慢指针     | 同方向不同速度               | 链表环检测、删除重复、找中点     |
| 滑动窗口     | 左右同向，右扩左缩           | 最长无重复子串、最小覆盖子串     |

**题目一：3Sum（LeetCode 15）**

```python
def threeSum(nums):
    nums.sort()
    result = []
    for i in range(len(nums) - 2):
        if i > 0 and nums[i] == nums[i-1]:
            continue  # 跳过重复
        lo, hi = i + 1, len(nums) - 1
        while lo < hi:
            s = nums[i] + nums[lo] + nums[hi]
            if s == 0:
                result.append([nums[i], nums[lo], nums[hi]])
                while lo < hi and nums[lo] == nums[lo+1]: lo += 1
                while lo < hi and nums[hi] == nums[hi-1]: hi -= 1
                lo += 1; hi -= 1
            elif s < 0:
                lo += 1
            else:
                hi -= 1
    return result
```

- 先排序 O(n log n)，然后固定一个数 + 双指针 O(n)，总 O(n²)
- 去重技巧：跳过与前一个相同的元素

---

**题目二：接雨水（LeetCode 42）—— 双指针 O(1) 空间**

```python
def trap(height):
    lo, hi = 0, len(height) - 1
    left_max = right_max = 0
    water = 0

    while lo < hi:
        if height[lo] < height[hi]:
            if height[lo] >= left_max:
                left_max = height[lo]
            else:
                water += left_max - height[lo]
            lo += 1
        else:
            if height[hi] >= right_max:
                right_max = height[hi]
            else:
                water += right_max - height[hi]
            hi -= 1

    return water
```

**核心逻辑**：对于每个位置，能接的水 = min(左边最高, 右边最高) - 当前高度。双指针维护两端最高值，较矮的一端向内移动时可以确定该位置的积水量。

**类比**：两堵墙从两边向中间靠拢——较矮的墙决定了当前位置的水位线。

**题目三：滑动窗口最大值（LeetCode 239）—— 单调队列**

```python
from collections import deque

def maxSlidingWindow(nums, k):
    dq = deque()  # 存下标，对应值单调递减
    result = []

    for i, num in enumerate(nums):
        # 移除窗口外的元素
        while dq and dq[0] < i - k + 1:
            dq.popleft()

        # 维护单调递减：新元素比队尾大，弹出队尾
        while dq and nums[dq[-1]] <= num:
            dq.pop()

        dq.append(i)

        # 窗口形成后记录结果
        if i >= k - 1:
            result.append(nums[dq[0]])

    return result
```

- 单调队列保证：队首始终是当前窗口的最大值
- 每个元素最多入队出队各一次 → O(n)

**追问**：如果需要同时维护窗口最大值和最小值怎么办？
→ 使用两个单调队列：一个单调递减（维护最大值），一个单调递增（维护最小值）。常用于"最长的满足 max-min ≤ k 的子数组"问题。

### Q28：堆（优先队列）如何用于中位数维护和 K 路归并？⭐⭐⭐

<details>
<summary>参考答案</summary>

**题目一：数据流中的中位数（LeetCode 295）**

**核心思路**：维护两个堆
- 大顶堆 `max_heap`：存储较小的一半
- 小顶堆 `min_heap`：存储较大的一半
- 保持 `len(max_heap) == len(min_heap)` 或 `len(max_heap) == len(min_heap) + 1`

```python
import heapq

class MedianFinder:
    def __init__(self):
        self.max_heap = []  # 存较小一半（取负值模拟大顶堆）
        self.min_heap = []  # 存较大一半

    def addNum(self, num):
        # 先放入大顶堆
        heapq.heappush(self.max_heap, -num)
        # 大顶堆的最大值移到小顶堆
        heapq.heappush(self.min_heap, -heapq.heappop(self.max_heap))
        # 平衡：如果小顶堆更多，移回一个
        if len(self.min_heap) > len(self.max_heap):
            heapq.heappush(self.max_heap, -heapq.heappop(self.min_heap))

    def findMedian(self):
        if len(self.max_heap) > len(self.min_heap):
            return -self.max_heap[0]
        return (-self.max_heap[0] + self.min_heap[0]) / 2
```

**类比**：把一排学生按身高分成两组——左组(矮)的最高 ≈ 右组(高)的最矮 → 中间就是中位数。

**题目二：K 路归并（LeetCode 23 — 合并 K 个有序链表）**

```python
import heapq

def mergeKLists(lists):
    heap = []
    for i, lst in enumerate(lists):
        if lst:
            heapq.heappush(heap, (lst.val, i, lst))

    dummy = cur = ListNode(0)
    while heap:
        val, i, node = heapq.heappop(heap)
        cur.next = node
        cur = cur.next
        if node.next:
            heapq.heappush(heap, (node.next.val, i, node.next))
```

| 场景                         | K 的含义                | N 的含义        |

### Q29：外部排序的原理是什么？多路归并和败者树各自的优势是什么？⭐⭐⭐

<details>
<summary>参考答案</summary>

**外部排序的场景**：数据量远大于内存，无法一次性加载排序。

**基本流程**：

```
阶段一：生成有序归并段（Run）
┌──────────────┐
│ 大文件(100GB) │
└──────────────┘
      │ 每次读取内存大小(1GB)的数据
      ▼
┌──────┬──────┬──────┬─────────┐
│Run 1 │Run 2 │Run 3 │ ... Run N│  每个 Run 内部有序
└──────┴──────┴──────┴─────────┘
      │
      ▼
阶段二：多路归并
  K 路归并（K = Run 数量）
  从每个 Run 读一个 buffer
  用堆/败者树选最小值输出
  哪个 buffer 空了就从对应 Run 补充
      │
      ▼
┌──────────────┐
│ 有序大文件    │
└──────────────┘
```

**I/O 优化**：

| 优化                 | 说明                                                   |
| -------------------- | ------------------------------------------------------ |
| 增大归并段           | 用**替换-选择排序**（败者树 + 输入缓冲），可以生成平均 2倍内存大小的 Run |
| 增加归并路数 K       | 减少归并轮数（轮数 = ⌈log_K(N)⌉），但 K 太大会导致每路 buffer 太小  |
| 双缓冲（预读）       | 一个 buffer 在用，另一个异步读取下一批数据，隐藏 I/O 延迟            |

**败者树 vs 最小堆**：

```
            败者树（Loser Tree）               最小堆（Min Heap）
时间复杂度   每次选最小值 O(log K)              每次 pop+push O(log K)
比较次数     每次 log₂K 次比较                  每次 2×log₂K 次比较（下沉要左右孩子都比）
Cache 友好   更好（比较路径固定，分支预测更准）   较差（堆的比较路径不固定）
实现复杂度   较高                               简单（标准库直接用）
```

**败者树原理**：

```
         [败者: B]        ← 根节点记录"败者"（较大的）
        /         \
   [败者: D]    [败者: C]
   /     \      /     \
  A       B    C       D    ← 叶子节点 = K 路输入

胜者（最小值）沿路径上升到根的"胜者位置"
每次取出根的胜者后，只需沿该叶子到根路径重新比赛 → log₂K 次比较
```

```python
class LoserTree:
    def __init__(self, k, initial_values):
        self.k = k
        self.tree = [0] * k        # 内部节点，存"败者"的索引
        self.leaves = list(initial_values)  # 叶子节点
        self._build()

    def _build(self):
        """从下往上构建败者树"""
        self.tree = [-1] * self.k
        for i in range(self.k):
            self._adjust(i)

    def _adjust(self, i):
        """叶子 i 的值变化后，沿路径向上调整"""
        parent = (i + self.k) // 2
        while parent > 0:
            if self.tree[parent] == -1 or self.leaves[i] > self.leaves[self.tree[parent]]:
                i, self.tree[parent] = self.tree[parent], i
            parent //= 2
        self.tree[0] = i  # 最终胜者

    def winner(self):
        return self.tree[0]  # 返回最小值所在的路索引

    def update(self, idx, new_val):
        self.leaves[idx] = new_val
        self._adjust(idx)
```

**追问**：如果 K 很大（如 1000 路），败者树和堆的性能差距有多大？
→ 理论上败者树的比较次数是堆的一半（log K vs 2log K），但现代 CPU 中，堆的实现更简单且标准库高度优化。实际工程中（如数据库的外部排序），两者性能差距在 10-20%。K 路太多时，瓶颈在 I/O 而非 CPU。

</details>

### Q30：TimSort 的设计思想是什么？为什么 Java 和 Python 都选择它作为默认排序算法？主定理（Master Theorem）如何分析分治算法复杂度？⭐⭐⭐

<details>
<summary>参考答案</summary>

**TimSort 的核心思想**：利用现实数据中常见的"部分有序"特征。

```
TimSort 三大设计：
1. 发现并利用已有的有序段（natural runs）
2. 对短段用二分插入排序（小数据插入排序比归并快）
3. 用策略性的归并规则保证 O(n log n) 最坏情况
```

**详细流程**：

```
输入数组：[5, 3, 1, 2, 4, 6, 8, 7, 9, 10]

步骤 1：扫描 natural runs（升序或降序段）
  Run 1: [5,3,1] → 检测到降序 → 翻转为 [1,3,5]
  Run 2: [2,4,6,8] → 升序
  Run 3: [7,9,10] → 升序

步骤 2：如果 run 太短（< minrun），用二分插入排序扩展到 minrun
  minrun 通常 = 32~64（取决于数组总长度）

步骤 3：将 runs 压入栈，按合并策略归并
  栈规则（保证 O(n log n)）：
    对于栈顶三个 run A, B, C：
    - 必须满足 |C| > |B| + |A| 且 |B| > |A|
    - 不满足时归并较小的两个
```

**为什么 TimSort 优秀**：

| 特性            | TimSort          | 快排              | 归并排序        |
| --------------- | ---------------- | ----------------- | --------------- |
| 最坏时间        | O(n log n)       | O(n²)             | O(n log n)      |
| 最好时间        | **O(n)** ✨      | O(n log n)        | O(n log n)      |
| 稳定性          | ✅               | ❌                | ✅              |
| 额外空间        | O(n)             | O(log n)          | O(n)            |
| 部分有序优化    | ✅ 极好          | ❌                | ❌              |
| 实际性能        | 极好             | 好                | 好              |

**现实数据往往是"几乎有序"的**（如日志按时间戳、数据库查询结果等），TimSort 能以接近 O(n) 处理这些数据。

---

**主定理（Master Theorem）**：

分析形如 `T(n) = a × T(n/b) + O(n^d)` 的递推关系。

```
T(n) = a × T(n/b) + O(n^d)

其中：
  a = 子问题数量
  b = 子问题规模缩小倍数
  d = 合并步骤的复杂度指数

比较 log_b(a) 和 d：

  情况 1：log_b(a) > d → T(n) = O(n^(log_b(a)))  [递归主导]
  情况 2：log_b(a) = d → T(n) = O(n^d × log n)    [均衡]
  情况 3：log_b(a) < d → T(n) = O(n^d)            [合并主导]
```

**经典算法的主定理分析**：

| 算法       | 递推             | a  | b  | d  | log_b(a) | 结果          |
| ---------- | ---------------- | -- | -- | -- | -------- | ------------- |
| 归并排序   | T(n)=2T(n/2)+O(n)| 2  | 2  | 1  | 1        | O(n log n)    |
| 二分搜索   | T(n)=T(n/2)+O(1) | 1  | 2  | 0  | 0        | O(log n)      |
| 快排(均摊)  | T(n)=2T(n/2)+O(n)| 2  | 2  | 1  | 1        | O(n log n)    |
| Strassen   | T(n)=7T(n/2)+O(n²)| 7 | 2  | 2  | 2.81     | O(n^2.81)     |
| Karatsuba  | T(n)=3T(n/2)+O(n)| 3  | 2  | 1  | 1.58     | O(n^1.58)     |

**追问**：主定理不适用于什么情况？
→ 当子问题规模不等（如快排最坏 T(n)=T(n-1)+O(n)）或合并步骤不是多项式时（如 T(n)=2T(n/2)+O(n log n)，需要用主定理的推广形式）。

</details>

### Q31：【场景题】设计一个搜索引擎的排序系统——如何对百万级搜索结果进行多因子排序并返回 Top-K？⭐⭐⭐

<details>
<summary>参考答案</summary>

**问题分解**：搜索引擎的排序 = 召回（Recall）→ 粗排（Pre-ranking）→ 精排（Ranking）→ 重排（Re-ranking）

```
用户查询 "Python 教程"
    │
    ▼ 召回层（倒排索引）
  100 万候选文档
    │
    ▼ 粗排层（轻量模型）
  1 万候选文档
    │
    ▼ 精排层（复杂模型）
  500 候选文档
    │
    ▼ 重排层（业务规则）
  Top-K 返回给用户
```

**各层排序策略**：

| 层次  | 数据量   | 排序方法                    | 延迟预算  |
| ----- | -------- | --------------------------- | --------- |
| 召回  | 百万级   | 倒排索引 + BM25/TF-IDF     | < 50ms   |
| 粗排  | 万级     | 轻量模型（双塔/点积）      | < 10ms   |
| 精排  | 千级     | 复杂模型（BERT/交叉注意力） | < 50ms   |
| 重排  | 百级     | 业务规则（去重/多样性/广告） | < 5ms    |

**Top-K 的高效算法**：

```python
import heapq

def top_k_documents(scored_docs, k):
    """
    scored_docs: 迭代器，每次产生 (score, doc_id)
    用小顶堆维护 Top-K，只需 O(k) 内存
    """
    heap = []
    for score, doc_id in scored_docs:
        if len(heap) < k:
            heapq.heappush(heap, (score, doc_id))
        elif score > heap[0][0]:
            heapq.heapreplace(heap, (score, doc_id))  # pop + push 一步完成

    return sorted(heap, reverse=True)  # 输出按分数降序
```

**多因子排序的融合**：

```python

    """多因子加权融合"""
    return (
        0.4 * doc.relevance_score +   # 相关性（BM25/语义相似度）
        0.2 * doc.freshness_score +   # 时效性（发布时间衰减）
        0.2 * doc.authority_score +   # 权威性（PageRank/引用数）
        0.1 * doc.click_rate +        # 用户行为（CTR 预估）
        0.1 * doc.quality_score       # 内容质量（长度/图文/专业度）
    )
```

**工程优化**：

1. **提前终止**：WAND（Weak AND）算法——利用每个 term 的最大贡献值，跳过不可能进入 Top-K 的文档
2. **分片并行**：将索引分为 N 个分片，每个分片并行计算局部 Top-K，最后归并
3. **缓存热门查询**：LRU 缓存高频查询的 Top-K 结果（命中率可达 30-50%）

**追问链**：

1. **BM25 和 TF-IDF 有什么区别？** → BM25 对词频做了饱和处理（k1 参数）和文档长度归一化（b 参数），实际效果优于 TF-IDF
2. **如何处理排序的实时性？** → 增量索引 + 定期全量重建。新文档先写入内存中的增量索引，查询时合并主索引和增量索引结果
3. **Learning to Rank 怎么训练？** → 收集用户点击日志，构建 pairwise 训练样本（点击的 > 未点击的），用 LambdaMART 或 BERT 训练排序模型

</details>

### Q32：【场景题】海量数据 Top-K 问题的完整解法——从单机到分布式。⭐⭐⭐

<details>
<summary>参考答案</summary>

**问题**：10 亿个数中找最大的 Top-100。

**方案一：小顶堆（单机内存足够存 K 个元素时）**

```python
import heapq

def top_k_heap(stream, k):
    """流式处理，内存 O(k)"""
    heap = []
    for num in stream:
        if len(heap) < k:
            heapq.heappush(heap, num)
        elif num > heap[0]:
            heapq.heapreplace(heap, num)
    return sorted(heap, reverse=True)
```

- 时间：O(N log K)
- 空间：O(K)
- 适用：K 远小于 N，数据可流式读取

**方案二：快速选择（单机能放下全部数据时）**

```python
import random

def quick_select(nums, k):
    """找第 K 大，平均 O(N)"""
    if len(nums) == 1:
        return nums[0]

    pivot = random.choice(nums)
    left = [x for x in nums if x > pivot]    # 大于 pivot
    mid = [x for x in nums if x == pivot]     # 等于 pivot
    right = [x for x in nums if x < pivot]    # 小于 pivot

    if k <= len(left):
        return quick_select(left, k)
    elif k <= len(left) + len(mid):
        return pivot
    else:
        return quick_select(right, k - len(left) - len(mid))
```

- 平均时间：O(N)（最坏 O(N²)，随机化后概率极低）
- 空间：O(N)
- 适用：数据能放内存，且需要精确的第 K 大

**方案三：分布式 MapReduce**

```
阶段 1：Map
  每个 Mapper 处理一个数据分片（~100MB）
  每个 Mapper 用小顶堆维护本地 Top-K

阶段 2：Reduce
  单个 Reducer 收集所有 Mapper 的 Top-K（共 M×K 个元素）
  用堆/排序得到全局 Top-K

  数据量：M 个 Mapper × K 个元素 = M×K ≪ N
```

**方案四：大数据中的近似方案——Count-Min Sketch + 堆**

当需要的是"出现频率 Top-K"（如最热门 URL）而非"最大值 Top-K"时：

```
Count-Min Sketch：
  d 行 × w 列的计数矩阵
  每个元素用 d 个哈希函数映射到 d 行
  查询频率 = min(d 个计数器的值)
  空间 O(d × w)，与元素数 N 无关

结合堆维护 Top-K：
  遍历数据流，用 CMS 估算每个元素频率
  用小顶堆维护估算频率最高的 K 个
```

**各方案对比**：

| 方案           | 时间复杂度  | 空间复杂度 | 精确性 | 适用场景            |
| -------------- | ----------- | ---------- | ------ | ------------------- |
| 小顶堆         | O(N log K)  | O(K)       | 精确   | 流式/单机，K 较小    |
| 快速选择       | O(N) 平均   | O(N)       | 精确   | 全量数据放内存       |
| MapReduce      | O(N/M logK) | O(K)×M     | 精确   | 分布式大规模         |
| CMS + 堆      | O(N)         | O(d×w+K)   | 近似   | 频率 Top-K，极大数据 |

**追问链**：

1. **10 亿个数去重后有多少？如何估算不重复数的数量？** → HyperLogLog 算法，12KB 内存可估算 2^64 个不重复元素，标准误差 0.81%
2. **如果 K 也很大（如 Top-100 万）怎么办？** → 堆不合适（log K 太大），改用分布式排序（如 Spark 的 sortBy + take）
3. **如何验证 Top-K 结果的正确性？** → 对小样本全量排序对比；或用更大的 K'（如 2K）做 Top-K，验证 K+1 到 2K 的元素是否都小于 Top-K

### Q33：【场景题】设计一个支持模糊匹配的自动补全系统——从 Trie 到工程化的完整方案。⭐⭐⭐

<details>
<summary>参考答案</summary>

**需求**：用户输入 "pyth"，返回 ["python", "python3", "pythagoras", ...]，按热度排序，延迟 < 50ms。

**方案一：Trie + 优先队列（单机版）**

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.top_k = []  # 预计算：以此节点为前缀的热门词

class AutoComplete:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word, frequency):
        node = self.root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
            # 维护每个前缀节点的 Top-K
            self._update_top_k(node, word, frequency, k=10)

    def _update_top_k(self, node, word, freq, k):
        # 检查是否已存在
        for i, (f, w) in enumerate(node.top_k):
            if w == word:
                node.top_k[i] = (freq, word)
                node.top_k.sort(reverse=True)
                return
        node.top_k.append((freq, word))
        node.top_k.sort(reverse=True)
        if len(node.top_k) > k:
            node.top_k.pop()

    def search(self, prefix):
        node = self.root
        for ch in prefix:
            if ch not in node.children:
                return []
            node = node.children[ch]
        return [(w, f) for f, w in node.top_k]
```

- 查询时间：O(L)，L = 前缀长度（无需遍历子树）
- 空间代价：每个节点存 Top-K 列表，空间放大 K 倍

**方案二：排序数组 + 二分搜索（工程优化）**

```python
import bisect

class BinarySearchAutoComplete:
    def __init__(self, words_with_freq):
        # 按字典序排序
        self.words = sorted(words_with_freq, key=lambda x: x[0])
        self.keys = [w for w, f in self.words]

    def search(self, prefix):
        # 二分找到前缀范围 [lo, hi)
        lo = bisect.bisect_left(self.keys, prefix)
        hi = bisect.bisect_left(self.keys, prefix[:-1] + chr(ord(prefix[-1]) + 1))

        candidates = self.words[lo:hi]
        # 按频率降序排序取 Top-K
        candidates.sort(key=lambda x: -x[1])
        return candidates[:10]
```

- 优势：内存紧凑（无指针开销），缓存友好
- 适用于静态词库或低频更新场景

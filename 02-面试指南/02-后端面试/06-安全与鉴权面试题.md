## ⭐ 基础题

1) **JWT 与 Session Cookie 的区别与选型？**  
**答：**JWT 自包含、服务端可无状态验证，适合跨服务；但撤销困难、体积大易泄露。Session Cookie 需服务端存储/集中式会话，撤销与权限变更简单。组合策略：短 JWT + 长 Refresh Opaque 存储于授权服务器。

2) **什么是 CSRF？如何防护？**  
**答：**攻击者利用受害者已登录状态，诱导其发起跨站请求。防护：SameSite Cookie、状态变更接口校验 CSRF Token、Referer/Origin 校验、对跨域请求使用双提交 Cookie，避免使用 GET 改写状态。

3) **XSS 的本质是什么？**  
**答：**在受信页面执行了攻击者脚本。防护：输出编码、CSP、禁用危险内联、输入校验、模板默认转义。

4) **RBAC 与 ABAC 的区别？**  
**答：**RBAC 通过角色管理权限，简单可读；ABAC 基于主体/资源/环境属性，灵活细粒度但策略复杂。可混合：核心用 RBAC，敏感资源用属性条件。

5) **为什么需要 Refresh Token？**  
**答：**减少频繁登录，同时缩短 Access Token 有效期降低泄露风险。Refresh Token 应存储可撤销（DB/Redis），支持旋转与黑名单。

## ⭐⭐ 进阶题

1) **JWT 撤销有哪些办法？**  
**答：**缩短 TTL；Refresh Token 旋转 + 黑名单；Access Token 使用 `jti` 与吊销列表；关键操作再查会话状态；或改用 Opaque Token + introspection。

2) **多租户系统如何防止越权？**  
**答：**服务端根据 Token/会话映射租户，不信任客户端传入租户；所有查询带租户条件；行级/Schema 隔离；租户范围写在策略引擎（OPA/Casbin）；审计租户维度。

3) **防重放与签名链路如何设计？**  
**答：**请求包含时间戳 + Nonce + 签名，服务端校验时间窗口与一次性使用；幂等键保证重试安全；对 Webhook 验证签名并设置回放窗口。

4) **如何在微服务中统一鉴权？**  
**答：**网关验证 Token、做粗粒度 RBAC 与限流；服务侧细粒度校验与租户隔离；策略引擎集中化（OPA sidecar/中控）；trace_id 贯穿审计。

5) **密码存储的安全实践？**  
**答：**使用 Argon2/Bcrypt/Scrypt，配置合适 cost；加盐、禁止自定义 hash；避免重用密码；限制登录尝试并告警异常。

6) **选择 JWT 还是 PASETO？**  
**答：**PASETO 约束算法、默认安全，避免“算法降级”；但生态相对少。若团队熟悉 JWT，需严格禁用 `none`/对称混用、限定算法、配合 kid 轮换。

## ⭐⭐⭐ 高阶题

1) **零信任在后端落地的关键环节？**  
**答：**强身份（MFA/FIDO2）、设备与网络态势评估、细粒度策略与持续验证、最小权限、强审计、动态风险评分决定二次验证或阻断。

2) **如何设计可回滚的授权策略变更？**  
**答：**策略即代码，版本控制；灰度发布策略；预计算影响范围（静态分析/影子评估）；变更日志与快速回滚通道。

3) **第三方 Webhook 如何安全验证？**  
**答：**共享密钥 HMAC 或公钥签名；时间戳与回放窗口；绑定 IP/域名；请求体签名并校验 Content-Type；失败重试需幂等。

4) **Token 旋转的竞态如何处理？**  
**答：**刷新时立刻失效旧 Refresh；在存储中写入“父子”链，旧 Token 再用时拒绝；Access Token 允许短时间并发刷新但使用新颁发为准。

5) **如何在审计日志中保护隐私？**  
**答：**脱敏（掩码/哈希）、少收集、分级访问控制；敏感字段单独加密；审计日志完整性保护（哈希链/不可变存储）。

## 🎯 场景题

1) **场景：JWT 泄露，如何应急？**  
**思路：**缩短 TTL；在黑名单记录 `jti`；强制全员刷新（旋转 Refresh）；轮换签名私钥并更新 kid；审计可疑操作。

2) **场景：多租户 API 被越权读取数据，如何补救？**  
**思路：**立即阻断可疑 Token；数据层加租户强过滤；审计回溯；对外安全公告与补偿；更新策略与测试防止回归。

3) **场景：Webhook 遭重放攻击，库存扣减重复执行**  
**思路：**加入时间戳+Nonce，服务端保存已用 Nonce；幂等键与去重表；签名校验失败告警；对历史订单回放校正。

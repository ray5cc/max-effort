## 参考答案

### Q2: LoRA 数学原理（★★★★★ 必考）

**核心回答**：

LoRA 的核心假设是：**预训练模型的权重更新矩阵 ΔW 是低秩的**。也就是说，虽然 ΔW 的维度很大（如 4096×4096），但它可以用两个小矩阵的乘积 B×A 来近似表示，其中 A ∈ R^(r×d_in)，B ∈ R^(d_out×r)，r 远小于 d。

**为什么低秩近似有效？**

1. **Intrinsic Dimensionality（内在维度）论证**：Aghajanyan et al. (2020) 发现，预训练模型微调时的有效参数空间维度远低于模型参数量。一个 175B 参数的 GPT-3，微调的内在维度可能只有几千。

2. **直觉类比**：想象一个 4096 维空间中的优化轨迹，虽然空间很大，但优化实际上在一个低维子空间中进行——就像在高维空间中走直线，只需要起点和方向（低维信息）就够了。

3. **训练过程**：
   - A 矩阵初始化为随机高斯分布
   - B 矩阵初始化为零（确保初始 ΔW = BA = 0，不改变原始模型行为）
   - 前向传播：h = W₀x + (α/r) × BAx
   - 只有 A 和 B 参与梯度更新，W₀ 完全冻结

4. **参数效率**：以 Llama-3.1-8B 的一个 Attention 层为例：
   - 全参数：4096 × 4096 = 16,777,216 参数
   - LoRA (r=16): 4096×16 + 16×4096 = 131,072 参数
   - 压缩比：128 倍

**追问：rank 选多大合适？**

根据经验：
- 简单任务（格式控制）：r=8 足够
- 中等任务（领域适配）：r=16-32
- 复杂任务（能力扩展）：r=64
- 更大的 r 不一定更好，因为过高的秩可能导致过拟合

**追问：为什么 alpha 通常设为 2×rank？**

α/r 是缩放因子。当 α=2r 时，缩放因子为 2，意味着 LoRA 的贡献是原始权重的适度补充。这个值是经验性的——太大会让 LoRA 更新主导原始权重（不稳定），太小则训练效果不明显。

### Q4: QLoRA 原理（★★★★★ 必考）

**核心回答**：

QLoRA 有三个关键技术创新：

**1. NF4（NormalFloat 4-bit）量化**：
- 神经网络权重通常近似正态分布 N(0, σ²)
- NF4 针对正态分布优化量化区间，使得信息损失最小
- 相比标准 INT4 均匀量化，NF4 的量化误差减少约 50%

**2. 双重量化**：
- 量化过程：每 64 个权重共享一个量化常数（FP32，32 bits）
- 双重量化：这些量化常数本身再做一次 FP8 量化
- 节省：对 65B 模型减少约 3GB 显存

**3. 分页优化器**：
- 利用 NVIDIA 的统一内存（Unified Memory）
- 当 GPU 显存不足时，优化器状态自动换入 CPU 内存
- 避免 OOM，代价是略微降速（换页开销）

**显存对比**：70B 模型
- 全参数微调：~1120 GB（需要 14+ 张 A100 80GB）
- LoRA (bf16)：~160 GB（需要 2 张 A100 80GB）
- QLoRA (NF4)：~38 GB（单张 A100 48GB 即可）

### Q5: DPO vs RLHF（★★★★★ 必考）

**RLHF 流程**：
1. SFT 阶段：用指令数据训练基础模型
2. RM 阶段：收集人类偏好数据 → 训练 Reward Model
3. PPO 阶段：用 RM 的打分信号通过 PPO 算法优化策略模型

**DPO 流程**：
1. SFT 阶段：同上
2. DPO 阶段：直接用偏好数据训练，通过隐式 Reward 优化

**本质区别**：
- RLHF 先学 "什么是好的"（训练 RM），再用这个标准优化模型
- DPO 证明：**最优策略可以直接从偏好数据推导**，不需要显式 RM
- DPO 的 Loss 函数本质上将 RM 的目标和策略优化合二为一

**DPO 优势**：
- 不需要训练和维护 Reward Model（少一个模型）
- 训练更稳定（无 PPO 的超参数敏感问题）
- 显存需求更低（不需要同时加载 4 个模型：SFT、RM、Policy、Reference）
- 实现更简单（10 行代码 vs 数百行）

**RLHF 仍有优势的场景**：
- 需要迭代优化（在线 RLHF，模型持续改进）
- 需要复杂的奖励函数（多目标优化）
- OpenAI 规模的场景（他们有足够工程资源应对复杂性）

### Q7: 灾难性遗忘

**问题**：微调后模型在目标任务上效果变好了，但通用能力（数学、代码、常识推理）急剧下降。

**原因**：领域数据分布与预训练数据分布差异大，训练时模型权重偏向领域数据，"忘记"了通用知识。

**解决方案**：

1. **数据混合**：训练数据中混入 20-30% 的通用对话数据
2. **LoRA 而非全参数微调**：LoRA 只修改小部分参数，原始能力保留更好
3. **低学习率**：全参数微调用更小的学习率（1e-5 级别）
4. **少训几个 epoch**：2-3 epoch 通常够了
5. **评估通用 benchmark**：训练过程中同时评估 MMLU、HumanEval 等通用基准
6. **正则化**：L2 正则化、KL 散度约束（限制模型偏离参考模型的程度）

### Q12: 完整微调 Pipeline（★★★★★ 场景题必考）

**完整方案**：

**Phase 1: 数据准备（1-2 周）**
- 数据来源识别（历史记录、人工标注、合成生成）
- 标注平台搭建（Label Studio）
- 标注规范制定 + 标注员培训
- 数据清洗管线：去重(MinHash) → 质量评分(GPT-4) → 格式校验(JSON Schema) → PII脱敏
- 数据版本管理（DVC + S3）

**Phase 2: 训练（3-5 天）**
- 基座模型选择（根据语言、规模、许可证）
- 超参数搜索（先小数据集 + 小 epoch 跑 3-5 组实验）
- 正式训练（LoRA/QLoRA，W&B 追踪实验）
- Checkpoint 管理

**Phase 3: 评估（3-5 天）**
- 自动评估：Benchmark + LLM-as-Judge
- 人工评估：随机抽样 100+ 条，多人评分
- 回归测试：通用能力是否退化
- A/B 测试设计

**Phase 4: 部署（2-3 天）**
- LoRA 合并 → 量化（AWQ/GGUF）
- 部署到 vLLM/SGLang
- 灰度发布（5% → 20% → 50% → 100%）
- 监控告警（Prometheus + Grafana）

### Q14: 7B 模型达到 GPT-4 效果

**方案**（限定特定任务场景，如代码审查）：

1. **高质量训练数据**：用 GPT-4 生成 10K+ 条高质量 (代码, 审查意见) 对，含 Chain-of-Thought 推理过程
2. **数据增强**：Evol-Instruct 方法进化指令复杂度，覆盖边界情况
3. **两阶段训练**：先 SFT 学格式和知识，再 DPO 提升回答质量
4. **推理时增强**：加入 RAG（检索代码规范文档）+ 工具调用（lint/test）
5. **评估**：在内部测试集上达到 GPT-4 95% 的效果即可上线
6. **成本对比**：7B 模型推理成本约为 GPT-4 的 1/100

**关键认知**：7B 不可能在所有任务上达到 GPT-4，但在**特定任务**上，通过优质数据 + 微调 + 推理增强，可以达到可用水平。

### Q17: Function Calling 微调

**训练数据构造**：

```json
{"messages": [
  {"role": "system", "content": "你有以下工具可用:\n[{\"name\":\"search\",\"parameters\":{...}}]"},
  {"role": "user", "content": "搜索最近的Python教程"},
  {"role": "assistant", "content": null, "tool_calls": [
    {"type": "function", "function": {"name": "search", "arguments": "{\"query\":\"Python教程\",\"sort\":\"date\"}"}}
  ]},
  {"role": "tool", "content": "[{\"title\":\"Python入门\",\"url\":\"...\"}]"},
  {"role": "assistant", "content": "我找到了一些最新的Python教程..."}
]}
```

**关键点**：
1. 必须覆盖多种工具、多种参数组合
2. 包含"不需要工具"的反例（模型直接回答）
3. 包含多工具链式调用的场景
4. 包含工具调用失败后的重试/换工具场景
5. 使用模型自带的 Chat Template 格式化工具调用
6. 评估指标：参数准确率、工具选择准确率、JSON 格式正确率
